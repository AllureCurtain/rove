# P5b 本地 HTML 预览威胁模型

> 状态：**Proposed / Not Implemented。这是威胁模型，不是实现，也不是验收报告。**
> 日期：2026-09-17（本轮新增）。
> 关联：[设计](./2026-09-17-pi-desktop-workbench-design.md) §7、[实施计划](../plans/2026-09-17-pi-desktop-workbench-implementation.md) P5b、[P0/P1a 证据报告](../plans/2026-09-17-pi-desktop-workbench-p0-evidence.md)。

实施计划 P5b 规定"先写威胁模型，再实现资源服务和面板"，且资源服务落点（`apps/api` 或独立受控进程）要按威胁模型选定并记录。本文件就是那一步。

## 1. 威胁对象

预览功能要执行的，是**工作区里用户自己项目产生的 HTML**。它既不是受信输入也不是完全不可信输入：

- 项目内容是用户写的，但可能来自 `git clone`、依赖文档、构建产物，用户未必读过每一行；
- HTML 一旦执行，其中的脚本以预览 origin 的身份运行，可以读取该 origin 下的一切资源并发起请求；
- 工作区内容可能包含凭据形状文件，而文件读取链路已经按密钥名过滤（`files.rs` 的 `is_secret_filename`），预览不能绕过这层。

因此威胁模型的核心问题是：**一个可执行 HTML 的预览会话，最多能拿到什么。**

## 2. 资产与信任边界

| 资产 | 当前位置 | 预览是否应可读 |
|---|---|---|
| 工作区内非密钥文件 | 已有 `GET /product/workspaces/{id}/files/*`，受路径监禁与密钥名过滤 | 是（仅当前预览根目录内） |
| 产品 API 令牌 | Desktop 经 `window.__ROVE_TOKEN__` 注入，浏览器部署经 `/api/*` 代理 | **否** |
| 产品 cookie / 会话 | 产品域 origin | **否** |
| Runtime StateIndex / ProductStore | 服务端进程 | **否** |
| 宿主持有的凭据（keyring） | Desktop 主进程 | **否** |
| 用户本机其他路径 | 工作区外 | **否** |

边界结论：预览必须运行在一个**与产品 origin 不同的 origin** 上，且该 origin 不携带产品凭据。这是本模型唯一不可让步的约束；其余都是程度选择。

## 3. 攻击面逐项

| # | 攻击面 | 后果 | 现有缓解 | 结论 |
|---|---|---|---|---|
| A1 | 预览页脚本读取产品令牌并调用产品 API | 以用户身份执行任意产品动作（创建 run、批准工具调用） | 无。`__ROVE_TOKEN__` 在同 origin 的 `window` 上 | **必须隔离 origin**；这是引入本功能的前提 |
| A2 | 预览页以产品 origin 发请求，携带 cookie | 同上，且浏览器自动附带凭据 | 无 | 同上 |
| A3 | 预览页请求工作区外路径 | 读取用户本机其他文件 | `join_safe` 拒绝绝对路径、`..`、符号链接越界 | 复用；预览资源服务必须走同一 `join_safe`，不得自建路径解析 |
| A4 | 预览页请求密钥形状文件（`.env`、`*.pem`） | 凭据泄露 | `is_secret_filename` 过滤 + 目录列举同样过滤 | 复用；预览必须复用同一过滤器 |
| A5 | 预览页向任意远端发起请求（SSRF/数据外传） | 把工作区内容外传 | 无 | 预览服务只服务本地静态资源，**不代取远程内容**；CSP `connect-src 'none'` |
| A6 | 相对路径资源越出预览根 | 同 A3 | 无（尚无预览） | 每个资源请求都过 `join_safe` 并以符号链接 canonicalize 复核 |
| A7 | 令牌可猜测或被日志记录 | 未授权访问预览 | 无 | 令牌随机、随预览会话创建与撤销；不进入日志、trace、报告、证据导出与截图 |
| A8 | 预览会话关闭后仍可访问 | 会话过期后资源仍暴露 | 无 | 关闭即撤销；服务端记录会话根目录并在关闭时移除 |
| A9 | 自动执行 `package scripts` 或构建 | 在用户机器上运行任意代码 | 无 | 预览**只**服务已有静态文件；不运行任何脚本、不触发构建 |
| A10 | 大文件/多文件/慢连接拖垮服务 | DoS | 文件读取已有字节上限 | 资源数量、单资源大小、总大小、超时、并发全部设上限 |
| A11 | 未信任项目被预览 | 越出项目访问判断 | 无 | 预览入口要求明确的用户动作，并沿用工作区根登记；不自动打开 |
| A12 | HTML 内 `<iframe>`/`<script src>` 指向 `file://` | 读本机文件 | 无 | 独立 origin + CSP 阻断 `file:`；`default-src 'none'` 之外只放开预览根 |
| A13 | 预览页改 write 工作区 | 用户文件被改 | 产品文件 API 全部只读 | 预览只读；不提供任何写路径 |

## 4. 落点选择

候选：`apps/api` 内新增路由，或独立受控进程。

选择 **`apps/api` 内新增受控路由**，理由：

- 已有 `files.rs` 的 `join_safe`、`is_secret_filename`、字节上限、`serve_file` 与 `require_regular_file` 可原样复用。A3/A4/A6/A10 的缓解因此是复用而不是重写，重写才会引入分歧。
- 独立进程要多一条进程间通道与一套独立的路径校验，攻击面更大而不是更小。
- Desktop 与浏览器部署都由同一 API 进程服务，行为一致，不出现"Desktop 安全、浏览器不安全"的分裂。

代价：预览服务与产品 API 同进程，因此 A1/A2 的隔离**不能靠进程隔离**，必须靠 origin 与令牌隔离。这提高了对下列设计的硬性要求：

- 预览路由组使用与产品 API 不同的 host（回环上不同端口，或不同 host 名），使浏览器把它当作独立 origin；
- 预览会话令牌与产品令牌是不同 secret，预览路由只接受预览令牌；
- 预览响应带 `Content-Security-Policy`、`Cross-Origin-Opener-Policy: same-origin`、`Cross-Origin-Resource-Policy: same-origin`，且不 `Set-Cookie`。

## 5. 明确不做

- 不做通用远程代理：不代取 `http(s)` 资源，因此 SSRF 与重定向跟随不在范围内（设计 §7 同）。
- 不自动运行 `package scripts`、构建或任何进程（A9）。
- 不以 `iframe`/`srcdoc` 直接内嵌当预览：那样脚本跑在产品 origin 上，A1/A2 立即成立。现有"HTML 源码读取"保持源码只读，不被称作可执行预览。
- 不提供返回/前进等浏览器导航承诺，除非平台能力已验证（P5c 范围）。

## 6. 实施前必须满足的门槛

1. origin 隔离与预览令牌落地，且有测试证明产品令牌在预览 origin 不可用（A1/A2）。
2. 预览资源服务复用 `join_safe` 与 `is_secret_filename`，并有绝对路径、`..`、符号链接越界、密钥名的负向用例（A3/A4/A6）。
3. 会话创建/关闭的令牌生命周期有测试：关闭后旧令牌失效，且令牌不出现在日志与证据导出中（A7/A8）。
4. 资源数量、大小、超时、并发上限有测试（A10）。
5. 未信任/未登记工作区的预览入口被拒绝，且有负向用例（A11）。
6. `docs/runtime/subsystems.md` 记录新路由与上述边界；OpenAPI 同步。

## 7. 本模型的已知不足

- 未在本机对任何真实攻击载荷做过验证；本文件是静态威胁分析。
- 未评估 macOS/Linux 上回环多 origin 的行为差异；未跑安装版。
- A1 的"产品令牌在预览 origin 不可用"依赖浏览器同源策略按预期执行，需以真实浏览器用例证明，不能只靠代码审读。

在这些门槛满足前，P5b 保持未实现。**本文件不授权实现。**
