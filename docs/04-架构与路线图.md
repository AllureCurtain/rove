## 2. 五条核心设计原则

| 原则 | 含义 | 来源 / 验证 |
|---|---|---|
| **P1 Core 是 library,接口是壳** | `core` 模块不依赖 CLI/HTTP/UI 代码;CLI/API/Web 都是消费方 | Claude Code 的 `query()` AsyncGenerator |
| **P2 一切接口都是 Trait** | `ModelClient` / `Tool` / `MemoryStore` / `StateStore` / `Hook` 都是 `trait`(用 `async-trait` 或 `impl Trait`) | 可替换、可测试、可 mock |
| **P3 流式默认** | 主循环基于 `impl Stream<Item = StreamEvent>`,事件流贯穿全栈,不做"先阻塞再改流式" | pico 的遗憾,Claude Code 的正解 |
| **P4 状态一等公民** | 每次 run 有 ULID `run_id`,落盘 trace/state/report,可中断/可 resume | pico 已对,继续放大 |
| **P5 Workspace 是产品边界** | 核心类型叫 `Workspace`;Repo 只是 Folder 的增强形态,不是唯一世界 | 见 07 产品定位 |
| **P6 拒绝大文件** | 单文件不超过 800 行,职责单一;`core` 按职责拆 5-8 个文件 | pico 的 60KB `runtime.py` 反面教材 |

## 3. 模块结构骨架 (Rust idiom)

**先单 crate 起步**,等 M5/M6 接口层多了,再拆 Cargo workspace。

├── README.md

│   ├── planner.md
│   └── tool_descriptions/

│   ├── main.rs                    # CLI binary 入口 (薄)
│   ├── lib.rs                     # library crate 入口
│   │
│   ├── core/                      # 不依赖任何接口

**模块依赖方向(单向,不允许反向)**:

```
interfaces ─→ core ─→ models / tools / memory / state / hooks
                  ↓
              config / errors / utils
```

`core` 永远不 `use crate::interfaces::*`;`models` / `tools` / `memory` 之间没有横向依赖,只通过 `core::traits` 暴露的 trait 交互。

**Cargo workspace 拆分时机**:M5 加 API 后,如果 `rove` 单 crate 编译变慢,拆成:
```
rove/
├── crates/
│   ├── rove-core/    # 核心 library
│   ├── rove-cli/     # CLI binary
│   ├── rove-api/     # HTTP server binary
│   └── rove-tools-*/ # 重型工具(如 RAG)可独立 crate
```

## 4. 路线图 (M0-M7)

> 时间预算相比原 Python 路径整体 +30-40%,反映 Rust 自写 SDK 和编译循环的真实成本。

### M0 骨架 (1.5 周)

**目标**:项目结构 + 最小可跑的单轮 agent。

**做什么**:
- `cargo new --lib rove` + src/main.rs binary
- `core/types.rs` 基础类型 (Message / Tool / Job / Event)
- `core/workspace.rs` 最小 `Workspace` + `WorkspaceKind::{Folder, Repo}` 探测
- `core/engine.rs` 最小主循环 (能跑一次,impl Stream)
- `models/openai_like.rs` 一个 provider 适配 (async-openai 封装)
- `tools/registry.rs` + `tools/builtins.rs` 一个 echo 工具
- `state/store.rs` 最小化版本 (能写 run_id 目录)
- `interfaces/cli/` clap derive 入口

**验收**:
- `rove "echo hello"` 跑通
- 在普通目录下识别 `Folder Workspace`;在 git 仓库下识别 `Repo Workspace`
- `.rove/runs/<run_id>/` 下生成 `trace.jsonl` 和 `report.json`
- 一个冒烟测试 `cargo test e2e` 通过

**下一步阻塞**:多轮循环 + 真实工具 + 真实模型 prompt

---

### M1 核心循环 (3-4 周)

**目标**:pico 现在 80% 的能力,但是更干净的实现 + Rust 类型保证。

**做什么**:
- 多轮主循环 (含 step / token / time limit)
- file / shell 工具,带 boundary (路径校验、命令白名单可选)
- Tool pipeline 显式 7 步 (schema → validate → input → pre-hook → permission → exec → post-hook+diff)
- 基础 working memory (recent files / task summary)
- 完整 trace + state + report 三件套
- ContextManager 雏形 (prefix / memory / history / current,带 budget)
- 错误处理 + retry (用 thiserror 类型化错误,不同失败码 LLM 看得到)
- FakeModelClient + 第一个 benchmark 任务
- approval policy (Ask / Auto / Never)
- **自写 Anthropic thin client** (DeepSeek 走 OpenAI 协议复用)

**验收**:
- 能跑通"读这个目录然后总结"任务
- 能跑通"修复一个简单测试"任务
- benchmark 有 3-5 个任务能通过
- 中断重启能 resume

**下一步阻塞**:长任务能力不足

---

### M2 Planner (2-3 周)

**目标**:从 ReAct 演化到轻量 Plan-and-Execute,支持十几步以上的长任务。

**做什么**:
- `core/planner.rs`:把"main goal"拆成显式 TODO 列表
- TODO 存进 `task_state` (可序列化、可 resume)
- 主循环改成"plan → execute step → re-plan if needed"
- TODO 可在执行过程中修改 (不是硬死的 plan)
- TODO 完成度作为终止条件之一

**验收**:
- 能跑通"分析整个项目并写一份报告"任务
- 能跑通"重构 X 模块,先列计划再执行"任务
- 长任务中断后 resume,planner 知道已完成到哪一步

**下一步阻塞**:还不能利用外部知识

---

### M3 RAG retriever (1-2 周)

**目标**:语义检索代码 / 文档,作为一个工具接进去。

**做什么**:
- `tools/rag.rs`:retrieve_code、retrieve_docs 两个工具
- ingestion 脚本 (二进制 `rove-index` 或子命令):chunker + embedder + lancedb 写入
- 向量库选 lancedb (Rust 原生,无悬念)
- M3 起步用 OpenAI embedding API,M3 末或后续按需切 candle 本地

**验收**:
- 能跑通"基于这份文档回答 X"任务
- 能跑通"找到相关代码并修改"任务,且引用准确

**下一步阻塞**:工具能力还是有限

---

### M4 MCP 客户端 (2-3 周)

**目标**:一次性接通市面所有 MCP server。

**做什么**:
- `tools/mcp_proxy.rs`:把 MCP server 暴露的 tool 注册为本 agent 的 tool
- 自写 MCP client (JSON-RPC 2.0 over stdio/SSE),或 vet 社区 crate
- MCP server 配置 (filesystem / github / postgres 等都能连)
- 工具 schema 自动从 MCP 拉取

**验收**:
- 接上 github MCP,能让 agent 创建 issue / PR
- 接上 filesystem MCP (Anthropic 官方),验证多 server 共存
- 工具能力指数级扩展

**下一步阻塞**:还只能 CLI 用

---

### M5 HTTP API (1.5 周)

**目标**:别人 / 自己的前端能 HTTP 调用 agent。

**做什么**:
- `interfaces/api/` 用 axum
- `POST /jobs` 创建异步任务,返回 job_id
- `GET /jobs/{id}/events` SSE 流式拿事件
- `GET /jobs/{id}/state` 拿当前状态
- `POST /jobs/{id}/cancel` 取消
- Job 抽象在 core 里 (M0 就预留),API 层只是壳
- (可选) 拆 Cargo workspace 成 rove-core + rove-cli + rove-api

**验收**:
- curl 能创建 job 并流式拿到事件
- 多 job 并发不互相串扰
- core 测试一行不改

**下一步阻塞**:没有可点的界面

---

### M6 Web UI (1-2 周)

**目标**:可发链接的可视化界面。

**做什么**:
- 路径 A (推荐):Next.js 独立项目
  - chat 界面 + 工具调用可视化 + plan 视图 + trace 时间线
  - 通过 rove HTTP API + SSE 通信
- 路径 B (临时):`gradio` 风格的极简 HTML,直接挂在 axum 上

**验收**:
- 能给朋友发链接展示
- 用户能看到 thinking / tool call / progress
- 长任务能展示 plan 进度

**下一步阻塞**:无,M0-M6 完整产品已就绪

### M7+ 后续可选方向 (按需)

| 方向 | 何时考虑 |
|---|---|

## 5. 时间预算汇总

| 阶段 | Python 路径 (原) | Rust 路径 (本) | 累计 |
|---|---|---|---|
| M0 | 1 周 | 1.5 周 | 1.5 周 |
| M1 | 2-3 周 | 3-4 周 | 5-6 周 |
| M2 | 2 周 | 2-3 周 | 7-9 周 |
| M3 | 1-2 周 | 1-2 周 | 8-11 周 |
| M4 | 1-2 周 | 2-3 周 | 10-14 周 |
| M5 | 1 周 | 1.5 周 | 11-15 周 |
| M6 | 1-2 周 | 1-2 周 | 12-17 周 |

## 6. 风险与回避

| 风险 | 表现 | 回避 |
|---|---|---|
| **过早抽象** | M1 就把 Hook 抽得很完美 | 先具体后抽象,Hook 等 M2 末有真需求再上 |
| **大单文件复发** | engine.rs 越长越胖 | 一旦 > 400 行就拆,800 行硬上限 |
| **接口和核心耦合** | core 突然 `use crate::interfaces::*` | CI 加 `cargo modules` 检查 (后期),review 时人肉盯 |
| **流式做半截** | 工具调用同步执行,只 LLM 是流式 | M1 开始就要求工具执行也 yield 中间事件 |
| **状态破坏向后兼容** | task_state 字段乱改,旧 run 不能 resume | task_state 加 `schema_version: u32`,迁移用 versioned deserialization |
| **benchmark 跑不动** | 跑 benchmark 要真实 API key | FakeModelClient 默认,真实 API 是可选 feature flag |
| **Anthropic SDK 自写难度** | 流式 + tool_use block 解析复杂 | 先实现 non-streaming + simple message,再加 streaming,再加 tool_use,逐步扩展 |
| **借用检查器 / async 卡壳** | 主循环里多个 owner 抢 history | Engine 持有 history 所有权,工具通过 trait 拿 &Context,不直接持 history |
| **prompt 改动要重编译** | 改一个字就 cargo build 30 秒 | **prompt 全部放 `prompts/` 目录,运行时加载** (Rust 编译期 include_str! 仅用于不变内容) |
| **过早锁死成代码 agent** | 类型和文档到处写 Repo,普通文件夹 / 桌面 / 浏览器很难接 | 核心只写 `Workspace`;`Repo` 是 `WorkspaceKind` 或 capability |
