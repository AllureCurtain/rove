### 1.2 业界参考

#### Claude Code

参考 `claude-code-analysis/analysis/01-architecture-overview.md` §3。**两层入口模式**:

- `cli.tsx` 是**入口分流器**(轻量):识别快路径,提前退出,避免加载完整应用
  - 快路径:`--version` / `--dump-system-prompt` / `remote-control` / `daemon` / `bg` / `runner`
  - 不命中再 `await import('./main.tsx')`
- `main.tsx` 是**主启动器**(完整初始化):装配 React/Ink/MCP/init/setup 等重型依赖

设计思想:普通快速命令不需要加载整个应用,启动速度快且副作用少。

#### pico

参考 `pico/pico/cli.py::build_agent()`:

```python
def build_agent(args):
    workspace = WorkspaceContext.build(args.cwd)
    store = SessionStore(workspace.repo_root + "/.pico/sessions")
    model = _build_model_client(args)
    session_id = args.resume
    if session_id == "latest":
        session_id = store.latest()
```

**做对的**:
- WorkspaceContext 探测
- SessionStore 单独抽象
- ModelClient 通过 `_build_model_client(args)` 工厂函数构造
- `--resume latest` 字符串别名

**不足**:
- 没有 fast-path 分流,每次都全套初始化
- 装配逻辑和 CLI 解析混在 cli.py 里,M5 加 API 时这块要重写
- ID 用字符串,容易串用

#### 工业实践扫描

| 实践 | 来源 | rove 采纳 |
|---|---|---|
| Two-stage entry (fast path + full init) | Claude Code、ripgrep、cargo | ✅ |
| Flag-based CLI + 少量子命令 | clap derive 双支持 | ✅ pico 一致 |
| DI 用 struct(而非全局 / 单例) | tokio、axum、ripgrep | ✅ EngineDeps struct |
| Config 多源优先级 | 12-factor:CLI > env > file > default | ✅ figment |
| `.rove/` 向上探测 | git、cargo、Claude Code | ✅ |
| Tokio runtime 按需启动 | clap + tokio 常见模式 | ✅ fast path 不创建 runtime |
| 错误统一收口 | anyhow at main、thiserror at lib | ✅ |

### 1.3 rove 设计

#### A. CLI 接口

```rust
// src/interfaces/cli/args.rs
use clap::Parser;

#[derive(Parser, Debug)]
#[command(name = "rove", version, about = "A stateful, recoverable agent harness")]
pub struct Cli {
    /// 一次性任务消息 (不填则进入 REPL)
    #[arg(value_name = "MESSAGE")]
    pub message: Option<String>,

    /// 工作目录 (默认当前目录)
    #[arg(long, value_name = "DIR")]
    pub cwd: Option<PathBuf>,

    /// 模型 provider
    #[arg(long, value_enum)]
    pub provider: Option<ProviderKind>,

    /// 具体模型名
    #[arg(long)]
    pub model: Option<String>,

    /// 审批策略
    #[arg(long, value_enum, default_value_t = ApprovalPolicy::Ask)]
    pub approval: ApprovalPolicy,

    /// 最大主循环步数
    #[arg(long, default_value_t = 50)]
    pub max_steps: u32,

    /// 恢复指定 session (传 "latest" 表示最近一次)
    #[arg(long, value_name = "SESSION_ID_OR_LATEST")]
    pub resume: Option<String>,

    #[command(subcommand)]
    pub command: Option<SubCommand>,
}

#[derive(clap::Subcommand, Debug)]
pub enum SubCommand {
    /// 打印当前生效的完整配置
    DumpConfig,
    /// 索引仓库 (M3)
    Index { path: PathBuf },
    /// 列出本地 sessions
    Sessions,
}

#[derive(clap::ValueEnum, Clone, Debug)]
pub enum ProviderKind { Openai, Anthropic, Ollama, Deepseek }

#[derive(clap::ValueEnum, Clone, Debug, Copy, Serialize, Deserialize)]
pub enum ApprovalPolicy { Ask, Auto, Never }
```

#### B. 主入口分发

```rust
// src/main.rs
fn main() -> anyhow::Result<()> {
    let cli = Cli::parse();
    init_tracing(&cli);

    // === fast path === (不创建 tokio runtime,不读 .rove/)
    match &cli.command {
        Some(SubCommand::DumpConfig) => {
            let cfg = Config::load_sync(&cli)?;
            println!("{}", toml::to_string_pretty(&cfg)?);
            return Ok(());
        }
        Some(SubCommand::Sessions) => {
            list_sessions(&cli)?;
            return Ok(());
        }
        _ => {}
    }

    // === full path === (创建 tokio runtime + Engine)
    let rt = tokio::runtime::Runtime::new()?;
    rt.block_on(async_main(cli))
}

async fn async_main(cli: Cli) -> anyhow::Result<()> {
    let deps = build_engine_deps(&cli).await?;
    let engine = Engine::new(deps);

    match (&cli.command, &cli.message) {
        (Some(SubCommand::Index { path }), _) => {
            interfaces::cli::index::run(&engine, path).await
        }
        (None, Some(msg)) => {
            interfaces::cli::oneshot::run(&engine, msg.clone()).await
        }
        (None, None) => {
            interfaces::cli::repl::run(&engine).await
        }
        _ => unreachable!("invalid combination guarded by clap"),
    }
}
```

> `--version` / `--help` 由 clap 自己处理(直接 exit),连我们代码都不进。

```rust
pub async fn build_engine_deps(cli: &Cli) -> anyhow::Result<EngineDeps> {

        state_store:  Arc::new(state_store),
        model_client: Arc::new(model_client),
        tools:        Arc::new(tools),
        memory:       Arc::new(memory),
        hooks:        Arc::new(hooks),
        config:       Arc::new(config),
    })
}
```

#### E. 设计模式总结

| 模式 | 在 rove 的体现 | 为什么用 |
|---|---|---|
| **Dependency Injection** (构造注入) | `Engine::new(deps: EngineDeps)`,deps 一次性传入 | 可测试、多接口复用、生命周期清晰 |
| **Adapter** | `trait ModelClient` + impl for OpenAI/Anthropic/Ollama | 各家 SDK 流式 shape 不同,trait 吃掉差异 |
| **Strategy** | `enum ApprovalPolicy { Ask, Auto, Never }` 配套行为 | 决策算法可换 |
| **Registry** | `ToolRegistry`、`HookRegistry` | 动态数量、按名字查找,MCP 接进来时关键 |
| **Factory Function** | `fn build_model_client(cfg) -> Arc<dyn ModelClient>` | 根据 config 返回不同实现,调用方无需知道具体类型 |
| **Newtype** (Rust 习语) | `struct SessionId(Ulid)` 三个 ID 各自包装 | 编译期防串用,pico 字符串的痛点 rove 改掉 |
| **Facade** | `Engine` 自己 | 接口层只看到一个 Engine,不需要知道 8 个子系统 |
| **Bridge / Trait Object** | `Arc<dyn ModelClient>` 而非具体类型 | 接口和实现解耦,fallback provider 零成本扩展 |

故意**不用**的反模式:**Singleton** / **Service Locator** / **God Object** / 装配层不上 **Builder**(8 个必填字段不适合)。

### 1.4 本站锁定决策

| # | 决策 | 选择 |
|---|---|---|
| 1.1 | 入口模式 | 两层入口:fast path + full path |
| 1.2 | CLI 风格 | flag-based + 少量子命令 (`dump-config`/`index`/`sessions`) |
| 1.3 | REPL 进入方式 | 不带 message 默认进 REPL (pico 风格) |
| 1.4 | 装配位置 | `interfaces/cli/wiring.rs`,**不在 core 里**;API 阶段并存 `interfaces/api/wiring.rs` |
| 1.5 | DI 容器 | `EngineDeps` struct + 全 `Arc<dyn Trait>` |
| 1.6 | ID 类型 | `SessionId` / `JobId` / `RunId` 各自 newtype 包 `Ulid` |
| 1.7 | 配置多源 | figment:CLI > env > `.rove/config.toml` > default |
| 1.8 | Workspace 探测 | 向上找 `.git` / `.rove/`,找不到用 cwd |
| 1.9 | 默认 ApprovalPolicy | `Ask` (用户安全优先,可改 `--approval auto`) |
| 1.10 | `Arc` 而非 `Rc` | 为 M5 多线程 API 准备,代价 0 |

## 站 2:`Engine::run()` 入口 + Job/Run 创建 (步骤 6)

**v1 (preliminary) — 2026-05-17**

### 2.1 命名:为什么是 `run()` 不是 `ask()`

pico 用了 `ask()`,rove 改为 `run()`。理由:

| 候选 | 来源 | 评价 |
|---|---|---|
| `ask` | pico | "ask"暗示问问题等答案,agent 是**执行任务**,语义不精准 |
| `query` | Claude Code | 在 Rust 圈和"数据库查询"绑定,语义偏狭 |
| `invoke` | LangChain | 框架味重,不用框架就别借这个味 |
| `chat` | OpenAI/Anthropic SDK | 暗示多轮对话,agent 是单次任务 |
| `generate` | Mastra | LLM 中心,我们要 agent 中心 |
| **`run`** | **Aider、smolagents、tokio、axum、clap** | **Rust idiom 最匹配**,短、清晰、诚实 |

**锁定**:`Engine::run(req: RunRequest) -> RunStream<'_>`

### 2.2 关注的问题

1. `run()` 的精确签名,返回类型怎么同时满足 CLI 直接消费 + API 异步 handle
2. Job 和 Run 真的两个都要吗?各自字段?
3. `.rove/runs/<run_id>/` 目录什么时候创建?
4. M0 必须的 `StreamEvent` 是哪几个?
5. 取消机制(显式 vs drop)
6. Session 新建 vs 恢复怎么分流?

### 2.3 业界参考

#### Claude Code

参考 `claude-code-analysis/analysis/05-differentiators-and-comparison.md` §2:

```typescript
export async function* query(
  userMessages: Message[],
  systemPrompt: SystemPrompt,
  toolUseContext: ToolUseContext,
  deps: QueryDeps,
): AsyncGenerator<StreamEvent>
```

**做对的**:返回 AsyncGenerator,所有接口共享同一份流。

**rove 不照搬**:Engine 在 rove 里是 struct(站 1 已确定 DI 容器模式),而非 free function。

#### pico

参考 `pico/pico/runtime.py::Pico.ask()`:

**做对的**:立即分配 run_id、立即写第一版 task_state.json、主循环用计数器守门。

**不足**:阻塞返回不是 stream;没有 Job 概念;缺乏显式 cancellation。

#### 工业实践扫描

| 实践 | 来源 | rove 采纳 |
|---|---|---|
| Return type 兼具 handle + stream | hyper `ResponseFuture`、axum `Sse` | ✅ `RunStream` 同时 impl `Stream` + 有 `cancel()` |
| Explicit cancellation token | `tokio_util::sync::CancellationToken` | ✅ |
| Drop-to-cancel | Future/Stream 默认行为 | ✅ 兜底 |
| Resume 通过传 ID 而非新方法 | gRPC bidi stream | ✅ `RunRequest.job_id` |
| RunStarted 必须最早 yield | Claude Code、OpenAI Realtime | ✅ |
| 目录在第一个 yield 之前创建 | filesystem-first | ✅ |

### 2.4 rove 设计

#### A. Engine::run 签名

```rust
// src/core/engine.rs
pub struct Engine {
    deps: EngineDeps,
}

impl Engine {
    pub fn new(deps: EngineDeps) -> Self {
        Self { deps }
    }

    /// 主入口:运行一个任务,返回事件流 + 控制 handle。
    /// 流被 drop 时自动取消。也可以显式 stream.cancel()。
    pub fn run<'e>(&'e self, req: RunRequest) -> RunStream<'e> {
```

#### C. RunStream(handle + stream 二合一)

```rust
use tokio_util::sync::CancellationToken;

pub struct RunStream<'e> {
    inner: Pin<Box<dyn Stream<Item = StreamEvent> + Send + 'e>>,
    job_id: JobId,
    run_id: RunId,
    cancel_token: CancellationToken,
}

impl<'e> RunStream<'e> {
    pub fn run_id(&self) -> RunId { self.run_id }
    pub fn job_id(&self) -> JobId { self.job_id }
    pub fn cancel(&self) { self.cancel_token.cancel(); }
}

impl<'e> Stream for RunStream<'e> {
    type Item = StreamEvent;
    fn poll_next(
        mut self: Pin<&mut Self>,
        cx: &mut std::task::Context<'_>,
    ) -> std::task::Poll<Option<Self::Item>> {
        self.inner.as_mut().poll_next(cx)
    }
}

impl<'e> Drop for RunStream<'e> {
    fn drop(&mut self) {
        self.cancel_token.cancel();
    }
}
```

**关键**:`run()` 同步返回 `RunStream`,**IDs 立刻可查询,不阻塞**。这对 API 模式特别关键(POST /jobs 立刻返回 job_id)。

#### D. Job 和 RunState

```rust
/// Job — 用户视角的"任务",生命周期跨越多个 Run
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Job {

#[serde(rename_all = "snake_case")]

/// RunState — 一次主循环执行的运行时状态
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RunState {
    pub id: RunId,
    pub job_id: JobId,

    pub ended_at: Option<DateTime<Utc>>,
    pub step: u32,
    pub status: RunStatus,
    pub termination_reason: Option<TerminationReason>,
    pub usage: Usage,
    pub schema_version: u32,
}

#[derive(Debug, Clone, Copy, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "snake_case")]
pub enum RunStatus { Init, Running, Done, Error, Cancelled }

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum TerminationReason {
    Final,
    StepLimit,
    TokenLimit,
    TimeLimit,
    Cancelled,
    Error { code: String },
}

#[derive(Debug, Clone, Default, Serialize, Deserialize)]

    pub input_tokens: u64,
    pub output_tokens: u64,
    pub cache_read_tokens: u64,
    pub total_cost_usd: Option<f64>,
}
```

**为什么 Job 和 Run 分两层**:

| 场景 | Job 视角 | Run 视角 |
|---|---|---|
| 一次顺利完成的任务 | 1 个 Job | 1 个 Run |
| LLM 输出格式错,系统 retry | 1 个 Job | 2 个 Run(前者 status=error) |
| step_limit 后用户 resume | 1 个 Job | 2 个 Run(前者 reason=step_limit) |
| API 取消任务 | `cancel(job_id)` | 内部所有 Run → cancelled |

#### F. 启动序列(`RunStream::start` 内部)

```rust
impl<'e> RunStream<'e> {
    fn start(engine: &'e Engine, req: RunRequest) -> Self {
        let cancel_token = CancellationToken::new();
        let job_id = req.job_id.unwrap_or_else(JobId::new);
        let run_id = RunId::new();
        let session_id = req.session_id.unwrap_or_else(SessionId::new);

        let cancel_clone = cancel_token.clone();
        let stream = async_stream::stream! {
            // [1] 校验请求
            if req.message.trim().is_empty() {
                yield StreamEvent::RunCompleted {
                    run_id, reason: TerminationReason::Error {
                        code: "empty_message".into()
                    },
                    usage: Usage::default(), final_output: None,
                    ended_at: Utc::now(),
                };
                return;
            }

            // [2] 解析 session(新建或加载)
            let session = engine.deps.state_store.resolve_session(session_id).await;

            // [3] 创建/恢复 Job
            engine.deps.state_store.upsert_job(Job {
                id: job_id, session_id, user_message: req.message.clone(),
                created_at: Utc::now(), status: JobStatus::Running,
                runs: vec![run_id], schema_version: 1,
            }).await;

            // [4] 创建新 Run + 目录 + 初始 task_state.json
            let run_state = RunState {
                id: run_id, job_id, session_id,
                started_at: Utc::now(), ended_at: None, step: 0,
                status: RunStatus::Init, termination_reason: None,
                usage: Usage::default(), schema_version: 1,
            };
            engine.deps.state_store.create_run(&run_state).await;
            // ^^^ 内部:mkdir .rove/runs/<run_id>/, 初始化 trace.jsonl

            // [5] 首个事件
            yield StreamEvent::RunStarted {
                run_id, job_id, session_id,
                user_message: req.message.clone(),
                started_at: run_state.started_at,
            };

            // [6] 转交主循环(站 6-7)
            for await event in engine.main_loop(
                run_id, job_id, session_id, req, cancel_clone,
            ) {
                yield event;
            }
        };

        Self {
            inner: Box::pin(stream),
            job_id, run_id, cancel_token,
        }
    }
}
```

**关键时序**:
- `start()` 同步返回,IDs 立刻可查
- 流被 poll 之前 0 I/O
- 首次 poll 才触发目录创建
- 第一个 yield 是 `RunStarted`,且目录此时已就绪

#### G. 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Iterator/Stream** | `RunStream: Stream<Item = StreamEvent>` | Rust 异步流式标准 |
| **Async Generator** | `async_stream::stream! { yield ... }` | 状态机式逻辑写成顺序代码 |
| **State Machine** | `RunStatus` / `JobStatus` 显式状态 + 转换 | Run 生命周期天然状态机 |
| **Template Method** | `start()` 固定 5 步初始化 | 主流程不变,各步可替换 |
| **Cancellation Token** | `tokio_util::sync::CancellationToken` | 显式 + drop 双支持 |
| **Combined Handle + Stream** | `RunStream` 一个类型两种用法 | CLI 当 stream,API 当 handle |
| **Lazy Initialization** | 流被 poll 才 I/O | fast path 不触发副作用 |
| **Newtype with Operations** | `JobId::new() -> Ulid` 集中生成 | 编译期防串用 |

故意**不用**:
- `Future<JobHandle>` + `handle.events()` 二步式 — CLI 多一步 await
- `RunRequest` 上 Builder — 字段少,过度设计
- 分 `run_oneshot()` / `run_resume()` — 都走 `run(req)`,通过 `job_id` 是否 None 分流

#### Claude Code

参考 `claude-code-analysis/analysis/05-differentiators-and-comparison.md` §2:

**做对的**:单一 `while (true)` 扁平结构;流式 yield 嵌套在 outer loop;工具调用通过 `extractToolUseBlocks` 拿出,**没有显式 parse**(因为 Anthropic 协议直接返回结构化 block)。

#### A. Engine 内部结构(组合根)

Engine 持有外部服务的 `Arc<dyn Trait>`(DI 而来),**自己拥有**内部 service:

**为什么 ContextManager / Parser / Executor 是 struct 不是 trait**:
- 没有多态需求(只有一种实现)
- 行为差异通过字段配置
- trait 抽象增加心智成本但收益 0
- 未来真要换实现,再升级成 trait(YAGNI)

**为什么 ModelClient / StateStore / MemoryStore 是 trait**:
- ModelClient:多 provider(OpenAI / Anthropic / Ollama),真多态
- StateStore / MemoryStore:测试要换 InMemory 跳过磁盘

#### B. main_loop 完整骨架

```rust
// src/core/engine.rs (continued)
use std::time::Instant;
use tokio_util::sync::CancellationToken;

impl Engine {
    pub(crate) fn main_loop<'e>(
        &'e self,
        run_id: RunId,
        job_id: JobId,
        session_id: SessionId,
        req: RunRequest,
        cancel: CancellationToken,
    ) -> impl Stream<Item = StreamEvent> + Send + 'e {
        async_stream::stream! {
            // ─── run-local 状态 (闭包内 owned) ───
            let cfg = self.resolve_effective_config(&req.overrides);
            let mut history = History::new(&req.message);
            let mut step: u32 = 0;
            let mut attempts: u32 = 0;
            let mut total_usage = Usage::default();
            let start_time = Instant::now();
            let deadline = start_time + cfg.time_budget;

            'outer: loop {
                // ─── 前置守门:取消 / step_limit ───
                if cancel.is_cancelled() {
                    yield self.run_done(run_id, TerminationReason::Cancelled, &total_usage, None);
                    return;
                }
                if step >= cfg.max_steps {
                    yield self.run_done(run_id, TerminationReason::StepLimit, &total_usage, None);
                    return;
                }
                step += 1;

                // ─── [7a] Context build ───
                let prompt = match self.context_manager
                    .build(&history, session_id, &cfg).await
                {
                    Ok(p) => p,
                    Err(_e) => {
                        yield self.run_done(run_id, TerminationReason::Error {
                            code: "context_build_failed".into(),
                        }, &total_usage, None);
                        return;
                    }
                };

                // ─── [7b] Model stream (chunk-level check cancel) ───
                let mut full_response = String::new();
                let mut step_usage = Usage::default();
                let mut model_stream = self.deps.model_client.stream(&prompt);

                while let Some(chunk) = model_stream.next().await {
                    if cancel.is_cancelled() {
                        yield self.run_done(run_id, TerminationReason::Cancelled, &total_usage, None);
                        return;
                    }
                    match chunk {
                        Ok(ModelChunk::Delta(d)) => {
                            full_response.push_str(&d);
                            yield StreamEvent::LlmStreamChunk { run_id, step, delta: d };
                        }
                        Ok(ModelChunk::Final(usage)) => { step_usage = usage; }
                        Err(e) => {
                            yield self.run_done(run_id, TerminationReason::Error {
                                code: e.error_code().into(),
                            }, &total_usage, None);
                            return;
                        }
                    }
                }

                total_usage.accumulate(&step_usage);
                yield StreamEvent::LlmMessage {
                    run_id, step,
                    full_text: full_response.clone(),
                    usage: step_usage.clone(),
                };

                // ─── [7c] Parse ───
                let action = self.parser.parse(&full_response);

                // ─── [7d] Dispatch ───
                match action {
                    Action::Final(text) => {
                        history.append_assistant(full_response);
                        yield self.run_done(run_id, TerminationReason::Final, &total_usage, Some(text));
                        return;
                    }
                    Action::Malformed { reason } => {
                        attempts += 1;
                        if attempts >= cfg.max_attempts_per_step {
                            yield self.run_done(run_id, TerminationReason::Error {
                                code: "max_attempts_exceeded".into(),
                            }, &total_usage, None);
                            return;
                        }
                        history.append_malformed_feedback(reason);
                        continue 'outer;
                    }
                    Action::ToolCall { call_id, name, args } => {
                        attempts = 0;
                        history.append_assistant_with_tool_call(&full_response, call_id, &name, &args);

                        // ─── [7e] Execute (长 await,select! 接 cancel) ───
                        yield StreamEvent::ToolCallStarted {
                            run_id, step, call_id,
                            name: name.clone(), args: args.clone(),
                        };

                        let tool_outcome = tokio::select! {
                            biased;
                            _ = cancel.cancelled() => {
                                yield self.run_done(run_id, TerminationReason::Cancelled, &total_usage, None);
                                return;
                            }
                            r = self.executor.run_tool(name.clone(), args.clone(), call_id, run_id) => r
                        };

                        match tool_outcome {
                            Ok(success) => {
                                history.append_tool_result(call_id, &success);
                                yield StreamEvent::ToolCallCompleted {
                                    run_id, step, call_id,
                                    affected_paths: success.affected_paths.clone(),
                                    output_summary: success.summary.clone(),
                                };
                            }
                            Err(err) => {
                                history.append_tool_failure(call_id, &err);
                                yield StreamEvent::ToolCallFailed {
                                    run_id, step, call_id,
                                    error_code: err.code_str().into(),
                                    error_message: err.to_string(),
                                };
                                // 工具失败不终止 run,LLM 看到失败码自己决定下一步
                            }
                        }
                    }
                }

                // ─── [7f] memory update ───
                if let Err(e) = self.deps.memory.observe_step(&history, step, run_id).await {
                    tracing::warn!(error = ?e, "memory observe failed, continuing");
                }

                // ─── [7g] state/trace persist ───
                let snapshot = RunSnapshot {
                    step, status: RunStatus::Running,
                    usage: total_usage.clone(),
                    last_action: action.summary(),
                };
                if let Err(e) = self.deps.state_store.snapshot_run(run_id, &snapshot).await {
                    tracing::error!(error = ?e, "state snapshot failed, aborting run");
                    yield self.run_done(run_id, TerminationReason::Error {
                        code: "state_persist_failed".into(),
                    }, &total_usage, None);
                    return;
                }

                // ─── [7h] budget check ───
                if total_usage.total_tokens() > cfg.max_total_tokens {
                    yield self.run_done(run_id, TerminationReason::TokenLimit, &total_usage, None);
                    return;
                }
                if Instant::now() >= deadline {
                    yield self.run_done(run_id, TerminationReason::TimeLimit, &total_usage, None);
                    return;
                }
            }
        }
    }

    fn run_done(
        &self, run_id: RunId, reason: TerminationReason,
        usage: &Usage, final_output: Option<String>,
    ) -> StreamEvent {
        StreamEvent::RunCompleted {
            run_id, reason, usage: usage.clone(),
            final_output, ended_at: Utc::now(),
        }
    }
}
```

#### C. model.stream yield 的实现方案选择

`async_stream::stream!` 宏的 `yield` 只能在外层闭包顶层,不能在嵌套 async block 或 `tokio::select!` 分支里。

| 方案 | 描述 | 优劣 |
|---|---|---|
| **A. 不用 select!,直接 next() + check** | M0 选择,每个 chunk 后 `cancel.is_cancelled()` | 简单可直接 yield;cancel 延迟 10-50ms,可接受 |
| B. mpsc channel 中转 | spawn task 读 stream + 监听 cancel,主 stream 从 channel yield | 完美 cancel 响应,但多 task 生命周期复杂 |
| C. 手写 Stream impl | 不用 async_stream,自己实现 poll_next | 控制强,代码量翻倍 |

**M0 锁定方案 A**:cancel 延迟一个 chunk 对用户体验完全无感,换简单度。Executor 单次长 await 不涉及 streaming,用 select! 没问题。

#### G. 计数器分工

| 计数器 | 何时 +1 | 何时重置 | 守门规则 |
|---|---|---|---|
| `step` | 每轮迭代开头 | 永不重置 | `>= max_steps` → StepLimit |
| `attempts` | malformed 时 +1 | 成功 parse 出 Final/ToolCall → 0 | `>= max_attempts_per_step` → Error |
| `total_usage` | 每次 model 调用后累加 | 永不重置 | `> max_total_tokens` → TokenLimit |
| 时间 | 自然流逝 | 永不重置 | `>= deadline` → TimeLimit |

**关键**:**step 在 malformed retry 时仍 +1**,意味着 step_limit 同时限制循环深度 + 防 retry 死循环,**两个目的一个计数器**。比 pico 双计数器更简洁,代价是 step_limit 数值要稍宽。

### 3.4 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Pipeline / Chain** | 7a → 7b → 7c → 7d → 7e → 7f → 7g → 7h 串行 | 主循环本质是数据流 pipeline |
| **State Machine** | step / attempts / usage 游标 + 6 个终止状态 | 每轮迭代是状态转移 |
| **Strategy** | ContextManager / Parser / Executor 可升级为 trait | 行为可替换,M0 不抽象避免过早抽象 |
| **Visitor (Action 分流)** | `match action { Final / Malformed / ToolCall }` | sum type + 穷尽 match,Rust 本命 |
| **Cancellation Propagation** | CancellationToken 在守门点 + 长 await 检查 | 协作式取消,响应 < 50ms |
| **Template Method (隐式)** | main_loop 固定 8 步骨架 | 主流程不变,各 service 内部独立演化 |
| **Owning Closure State** | history / step / usage 在 `stream!` 闭包内 owned | 单 Run 单 owner,无锁 |
| **Composition Root** | `Engine::new()` 一处构造所有内部 service | 依赖图集中可见 |

故意**不用**:
- **Observer**:各 service 不互发事件,事件流唯一来源是主循环 yield
- **State 模式**(每状态一个 struct):RunStatus 用 enum 就够
- **Coroutine pause/resume 接 input**:Rust 没有 Python 的 generator `send()`,也不需要

### 3.5 锁定决策

| # | 决策 | 选择 |
|---|---|---|
| 3.1 | `main_loop` 位置 | Engine 的 `pub(crate)` 方法,不是 free function |
| 3.2 | 循环结构 | 单一 `loop {}`,扁平,不嵌套 |

### 4.2 业界参考

#### Claude Code
直接用 `@anthropic-ai/sdk`,单 provider,无 routing。

#### pico
`pico/pico/models.py` 三个 client (Ollama / OpenAICompatible / AnthropicCompatible) 各 impl `complete()`。**做对的**:统一接口、provider 差异在适配器吃掉。**没做的**:routing、熔断、TTFB。

#### ragent (本站主参考)

参考 `ragent/docs/resume-highlights/highlight-03-circuit-breaker-ttfb.md`。

**核心洞察**:
- 流式调用的成败判定时机和同步调用本质不同 — 句柄返回 ≠ 调用成功
- **commit 边界**:第一个有效内容到达前可切候选,**到达后绝对不能切**(否则用户看到前一个模型的残片 + 后一个模型的完整答案)
- **双层健康判断**:熔断器(粗筛,看历史健康度)+ TTFB probe(细筛,看当次实时状态)
- **三态熔断器**:CLOSED → OPEN → HALF_OPEN,HALF_OPEN **只放一次试探性流量**,不周期性探测
- `ProbeStreamBridge` 在真实 callback 前缓冲 + 探测

**Rust 实现的天然简化**:Rust Stream 是 pull-based,**消费方不 poll 就没人推**。"探测期不下发"在 Rust 里等于"自己不调 yield"。ragent 那边的"buffer + commit 时回放 + 加锁"被压缩成 "first_delta + rest stream"。

但**架构思想完全保留**:三态熔断、TTFB probe、commit 边界、双层互补判断。

### 4.3 rove 设计

#### A. ModelClient trait (单 provider 关注点)

```rust
// src/models/traits.rs
use async_trait::async_trait;
use futures::Stream;
use std::pin::Pin;

#[async_trait]
pub trait ModelClient: Send + Sync {
    fn id(&self) -> &ModelClientId;

    /// 流式调用。返回 Stream 必须保证:
    /// - 第一个 Delta 之前的失败用 Err(ModelError) yield
    /// - 第一个非空 Delta yield 之后就是 commit boundary
    /// - 最末 yield 一次 Final(usage) 或 Err
    fn stream<'a>(
        &'a self,
        prompt: &'a Prompt,
    ) -> Pin<Box<dyn Stream<Item = Result<ModelChunk, ModelError>> + Send + 'a>>;
}

#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct ModelClientId(pub String);  // e.g. "openai/gpt-5.4"

pub enum ModelChunk {
    Delta(String),  // commit-worthy
    Final(Usage),
}
```

**关键约定**:**第一个非空 `Delta` 是 commit boundary**。实现者必须保证之前任何错误用 `Err(_)` 报告,之后不能撤回。

```rust
// src/models/openai_like.rs
pub struct OpenAICompatibleClient {
    id: ModelClientId,
    inner: async_openai::Client<async_openai::config::OpenAIConfig>,
    model: String,
}

#[async_trait]
impl ModelClient for OpenAICompatibleClient {
    fn id(&self) -> &ModelClientId { &self.id }

    fn stream<'a>(
        &'a self,
        prompt: &'a Prompt,
    ) -> Pin<Box<dyn Stream<Item = Result<ModelChunk, ModelError>> + Send + 'a>> {
        Box::pin(async_stream::stream! {
            let request = match self.build_request(prompt) {
                Ok(r) => r,
                Err(e) => { yield Err(e); return; }
            };
            let mut stream = match self.inner.chat().create_stream(request).await {
                Ok(s) => s,
                Err(e) => { yield Err(ModelError::from_openai(e)); return; }
            };
            let mut total_usage = Usage::default();
            while let Some(response) = stream.next().await {
                match response {
                    Ok(chunk) => {
                        if let Some(choice) = chunk.choices.first() {
                            if let Some(content) = &choice.delta.content {
                                yield Ok(ModelChunk::Delta(content.clone()));
                            }
                            // tool_calls 字段 M1 末再处理
                        }
                        if let Some(usage) = chunk.usage {
                            total_usage.accumulate_from_openai(&usage);
                        }
                    }
                    Err(e) => { yield Err(ModelError::from_openai(e)); return; }
                }
            }
            yield Ok(ModelChunk::Final(total_usage));
        })
    }
}
```

#### E. 多模型路由架构 (M2,借鉴 ragent)

```rust
// src/models/routing.rs

/// 多 provider routing,impl 同一个 ModelClient trait
/// Engine 完全不知道这层存在
pub struct RoutingModelClient {
    candidates: Vec<Arc<dyn ModelClient>>,
    health: Arc<ModelHealthStore>,
    probe_timeout: Duration,
    id: ModelClientId,
}

#[async_trait]
impl ModelClient for RoutingModelClient {
    fn id(&self) -> &ModelClientId { &self.id }

    fn stream<'a>(
        &'a self,
        prompt: &'a Prompt,
    ) -> Pin<Box<dyn Stream<Item = Result<ModelChunk, ModelError>> + Send + 'a>> {
        Box::pin(async_stream::stream! {
            let mut last_error = None;
            for candidate in &self.candidates {
                // 1. 熔断器粗筛
                if !self.health.allow_call(candidate.id()) {
                    tracing::debug!(candidate = ?candidate.id(), "skipped: circuit open");
                    continue;
                }

                // 2. 启动候选流 + TTFB probe
                let inner = candidate.stream(prompt);
                match probe_first_packet(inner, self.probe_timeout).await {
                    ProbeOutcome::Committed { first_delta, mut rest } => {
                        // ✅ commit 之后所有内容都是这个 candidate 的
                        self.health.mark_success(candidate.id());
                        yield Ok(ModelChunk::Delta(first_delta));
                        // 直通后续流。**commit 后不再 fallback**,失败直接报错
                        while let Some(chunk) = rest.next().await {
                            yield chunk;
                        }
                        return;
                    }
                    ProbeOutcome::Failed(err) => {
                        // ❌ 首包前失败,标记失败 + 试下一个
                        if err.counts_as_health_failure() {
                            self.health.mark_failure(candidate.id());
                        }
                        last_error = Some(err);
                        continue;
                    }
                }
            }
            yield Err(ModelError::AllCandidatesFailed {
                last: Box::new(last_error.unwrap_or(ModelError::NoCandidates)),
            });
        })
    }
}

/// TTFB probe — Rust Stream 模型下极简
enum ProbeOutcome<S> {
    Committed { first_delta: String, rest: S },
    Failed(ModelError),
}

async fn probe_first_packet<S>(
    mut stream: S,
    timeout: Duration,
) -> ProbeOutcome<S>
where
    S: Stream<Item = Result<ModelChunk, ModelError>> + Unpin,
{
    loop {
        match tokio::time::timeout(timeout, stream.next()).await {
            Ok(Some(Ok(ModelChunk::Delta(d)))) if !d.is_empty() => {
                return ProbeOutcome::Committed { first_delta: d, rest: stream };
            }
            Ok(Some(Ok(ModelChunk::Delta(_)))) => continue,
            Ok(Some(Ok(ModelChunk::Final(_)))) => return ProbeOutcome::Failed(ModelError::NoContent),
            Ok(Some(Err(e))) => return ProbeOutcome::Failed(e),
            Ok(None) => return ProbeOutcome::Failed(ModelError::EmptyStream),
            Err(_) => return ProbeOutcome::Failed(ModelError::ProbeTimeout),
        }
    }
}
```

**Rust 实现 vs ragent (Java) 差异**:

| ragent (Java) | rove (Rust) |
|---|---|
| `buffer.add()` 和 `commit()` 并发要加锁 | Stream 单 owner,无锁 |
| `CompletableFuture<ProbeResult>` 跨线程传递首包结果 | `stream.next().await` 直接拿 |
| 缓冲事件包装 Runnable + commit 时回放 | "first_delta + rest stream" 两个值 |
| `bufferOrDispatch` 双路径分支 | `match` 一行 |

#### F. 三态熔断器

```rust
// src/models/health.rs
use dashmap::DashMap;

pub struct ModelHealthStore {
    inner: DashMap<ModelClientId, HealthState>,
    config: HealthConfig,
}

#[derive(Debug, Default)]
struct HealthState {
    status: CircuitStatus,
    consecutive_failures: u32,
    last_failure_at: Option<Instant>,
    half_open_token: bool,
}

#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
pub enum CircuitStatus { #[default] Closed, Open, HalfOpen }

#[derive(Debug, Clone)]
pub struct HealthConfig {
    pub failure_threshold: u32,         // default 3
    pub open_cooldown: Duration,        // default 30s
    pub half_open_max_concurrent: u32,  // default 1
}

impl ModelHealthStore {
    pub fn allow_call(&self, id: &ModelClientId) -> bool {
        let mut entry = self.inner.entry(id.clone()).or_default();
        match entry.status {
            CircuitStatus::Closed => true,
            CircuitStatus::Open => {
                // 冷却期到了 → 升 HalfOpen
                if let Some(t) = entry.last_failure_at {
                    if t.elapsed() >= self.config.open_cooldown {
                        entry.status = CircuitStatus::HalfOpen;
                        entry.half_open_token = true;
                    }
                }
                if entry.status == CircuitStatus::HalfOpen && entry.half_open_token {
                    entry.half_open_token = false;
                    true
                } else { false }
            }
            CircuitStatus::HalfOpen => {
                if entry.half_open_token {
                    entry.half_open_token = false;
                    true
                } else { false }
            }
        }
    }

    pub fn mark_success(&self, id: &ModelClientId) {
        let mut entry = self.inner.entry(id.clone()).or_default();
        entry.status = CircuitStatus::Closed;
        entry.consecutive_failures = 0;
        entry.half_open_token = true;
    }

    pub fn mark_failure(&self, id: &ModelClientId) {
        let mut entry = self.inner.entry(id.clone()).or_default();
        entry.consecutive_failures += 1;
        entry.last_failure_at = Some(Instant::now());
        if entry.consecutive_failures >= self.config.failure_threshold {
            entry.status = CircuitStatus::Open;
        }
    }
}
```

**关键设计**:
- `DashMap` 而非 `Mutex<HashMap>`:并发读写多个 model id 时锁粒度细
- `half_open_token: bool` 实现 "HalfOpen 只放一次试探流量"(ragent 的核心设计)
- 冷却期到 → 自动升 HalfOpen(被动,不周期主动探测)

### 4.4 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Adapter** | `OpenAICompatibleClient` / `AnthropicCompatibleClient` impl `ModelClient` | 各 SDK 形状不同,trait 吃掉差异 |
| **Decorator** | `RoutingModelClient` 包多个 `ModelClient`,自己也是 `ModelClient` | Engine 透明,routing 零侵入 |
| **Circuit Breaker** | `ModelHealthStore` 三态 | 防止反复试已挂的 provider |
| **State Machine** | CircuitStatus 三态 + 转换规则 | 熔断器本质就是状态机 |
| **Token Bucket (简化)** | `half_open_token: bool` 只放一次试探 | ragent 设计的核心,rove 照搬 |
| **Strategy** | `probe_first_packet` 可换不同策略 | M2+ 可调 |
| **Pipeline** | prompt → request → http → sse → ModelChunk | 适配器内部就是 pipeline |
| **Newtype** | `ModelClientId(String)` | 类型隔离 |

故意**不用**:
- **Retry-as-decorator**:retry 策略和错误分类耦合,在 RoutingModelClient 内部处理更紧凑
- **Random load balance**:严格按用户配置优先级,不随机
- **HALF_OPEN 周期性主动探测**:ragent 反对,只放一次被动试探,照搬

| # | 决策 | 选择 |
|---|---|---|
| 4.1 | `ModelClient` 是 trait | ✅ async-trait |
| 4.2 | Message content 风格 | parts[] (Anthropic 风格) |
| 4.3 | `ModelChunk` 变体 (M0) | `Delta(String)` / `Final(Usage)`;M1 末加 `ToolUse {..}` |
| 4.4 | commit boundary | 第一个**非空** `Delta` |
| 4.5 | M0 provider | OpenAI-compatible(DeepSeek / right.codes / 本地 vLLM) |
| 4.6 | M1 provider | 自写 Anthropic thin client |
| 4.7 | M2 routing | `RoutingModelClient` impl 同 trait |
| 4.8 | 熔断器三态 | CLOSED / OPEN / HALF_OPEN |
| 4.9 | HALF_OPEN 行为 | 只放一次试探流量,不周期主动探测 |
| 4.10 | HealthStore 数据结构 | `DashMap<ModelClientId, HealthState>` |
| 4.11 | HealthStore 持久化 | M2 纯内存,M3 末考虑落盘 |

```rust
        &self,
        history: &History,
        session_id: SessionId,
```

#### E. 裁剪策略

```rust
fn fit_to_budget(&self, budgets: &mut SectionBudgets, total: u32) {
    let mut order: Vec<PromptSection> = vec![
        PromptSection::RelevantMemory,
        PromptSection::SessionSummary,
        PromptSection::History,
        PromptSection::DurableMemory,
        PromptSection::ToolsSchema,
    ];

    loop {
        let used: u32 = budgets.actuals.values().sum();
        if used <= total { return; }

        let over = used - total;
        let Some(target) = order.first().copied() else {
            tracing::error!("cannot fit prompt within budget");
            return;
        };
        let current = *budgets.actuals.get(&target).unwrap_or(&0);
        if current == 0 { order.remove(0); continue; }

        let cut = over.min(current);
        *budgets.actuals.entry(target).or_insert(0) -= cut;
        if *budgets.actuals.get(&target).unwrap_or(&0) == 0 {
            order.remove(0);
        }
    }
}
```

#### F. History 裁剪(老的先丢,因果对保留)

```rust
fn truncate_history(messages: &[Message], target_tokens: u32) -> Vec<Message> {
    let preserved_tail = 4; // 永远保留最后 4 条
    let mut result: Vec<Message> = messages.iter().rev().take(preserved_tail).rev().cloned().collect();
    let mut remaining = target_tokens.saturating_sub(estimate_tokens(&result));
    for msg in messages.iter().rev().skip(preserved_tail) {
        let cost = estimate_tokens_msg(msg);
        if cost > remaining { break; }
        // insert at proper position to preserve order
        remaining -= cost;
    }
    // ⚠️ 强制 ToolUse / ToolResult 配对完整
    enforce_tool_pairs(result)
}

fn enforce_tool_pairs(mut msgs: Vec<Message>) -> Vec<Message> {
    let tool_uses: HashSet<Ulid> = msgs.iter()
        .flat_map(|m| m.content.iter().filter_map(|p|
            if let MessagePart::ToolUse { call_id, .. } = p { Some(*call_id) } else { None }))
        .collect();
    msgs.retain(|m| m.content.iter().all(|p|
        if let MessagePart::ToolResult { call_id, .. } = p {
            tool_uses.contains(call_id)
        } else { true }));
    msgs
}
```

**关键**:不能裁掉一个 `ToolUse` 而留它对应的 `ToolResult`(反之亦然),否则 LLM 看到孤立 ToolResult 会困惑。

#### H. Compact 机制 (M2+)

```rust
pub struct CompactPolicy {
    pub trigger_threshold: f32,   // default 0.8(history 占比超 history budget × 0.8 触发)
    pub keep_recent_messages: u32, // default 6(保留最近 N 条不压缩)
    pub compact_model: Option<ModelClientId>,
}

async fn maybe_compact(
    &self,
    history: &mut Vec<Message>,
    session_id: SessionId,
) -> Result<bool, ContextError> {
    // [Tier 1] feature flag 关 → 不 compact,留给硬截断处理
    if !self.config.feature_flags.compact_enabled { return Ok(false); }

    let total = self.token_counter.count_messages(history);
    let threshold = self.config.engine.history_budget * self.config.compact.trigger_threshold;
    if (total as f32) < threshold { return Ok(false); }

    let keep_n = self.config.compact.keep_recent_messages as usize;
    let to_compact = &history[..history.len().saturating_sub(keep_n)];
    let preserved = &history[history.len().saturating_sub(keep_n)..];

    // [Tier 0] 调用 compact LLM
    match self.call_compact_llm(to_compact).await {
        Ok(summary) => {
            let summary_msg = Message::system_summary(&summary);
            *history = vec![summary_msg].into_iter().chain(preserved.iter().cloned()).collect();
            self.memory.save_session_summary(session_id, &summary).await?;
            Ok(true)
        }
        // [Tier 2/3] LLM 调用失败 / 解析失败 → 硬截断
        Err(e) => {
            tracing::warn!(error=?e, "compact LLM failed, hard truncate");
            *history = preserved.to_vec();
            Ok(true)
        }
    }
}

async fn call_compact_llm(&self, messages: &[Message]) -> Result<String, ModelError> {
    // 参考 ragent:utility LLM 参数
    let request = ModelRequest {
        system: COMPACT_SYSTEM_PROMPT.to_string(),
        messages: messages.to_vec(),
        temperature: 0.1, top_p: 0.3, thinking: false, max_tokens: 1024,
    };
    self.compact_model_client.as_ref()
        .ok_or(ModelError::Other("no compact model".into()))?
        .complete(request).await
}
```

**三层降级**(借鉴 ragent):

| Tier | 条件 | 行为 |
|---|---|---|
| 0 | LLM 调用成功 + 解析成功 | 用摘要替换老 history |
| 1 | feature flag 关 | 不 compact,在 fit_to_budget 阶段硬截断 |
| 2 | LLM 调用失败 | 硬截断老 history(无摘要) |
| 3 | LLM 输出空 / parse 失败 | 同 Tier 2 |

#### I. Token 计数策略

```rust
pub struct TokenCounter { mode: TokenCountMode }

pub enum TokenCountMode {
    Estimate { chars_per_token: f32 },           // 默认 1.5(中英混合经验值)
    TiktokenOpenAI { encoder: tiktoken_rs::CoreBPE }, // M2+ 选 OpenAI 家族精确
}

impl TokenCounter {
    pub fn count(&self, text: &str) -> u32 {
        match &self.mode {
            TokenCountMode::Estimate { chars_per_token } => {
                (text.chars().count() as f32 / chars_per_token) as u32
            }
            TokenCountMode::TiktokenOpenAI { encoder } => {
                encoder.encode_with_special_tokens(text).len() as u32
            }
        }
    }
}
```

**M0-M1 选 Estimate 的理由**:
- 0 依赖
- 偏保守 → budget 永不超 → 安全
- 通过 model 返回的 `Final(usage)` 反馈长期校准

### 5.4 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Builder (隐式)** | `gather → allocate → fit → compose` 四步 | 每步独立单测 |
| **Strategy** | `TokenCountMode` 切估算 vs 精确 | 不同 provider / milestone 选不同 |
| **Template Method** | `build()` 固定四步骨架 | 跟 Engine 主循环同套思路 |
| **Priority Queue** | `truncate_priority()` 给 section 排序 | 裁剪有明确策略 |
| **Three-tier Fallback** | compact 失败 → 硬截断;flag 关 → 不 compact | 借鉴 ragent |
| **Cache-aware Composition** | breakpoint 和 section 边界对齐 | Anthropic prompt cache 最大化 |
| **Newtype** | `PromptSection` enum 而非 string | 编译期保证 |

故意**不用**:完整 Chain of Responsibility(每 section 一个 builder,过度抽象);动态 section 注册(YAGNI)。

#### E. Parser struct(无 trait)

```rust
// src/core/parser.rs
pub struct Parser { config: ParserConfig }

#[derive(Debug, Clone)]
pub struct ParserConfig {
    pub treat_empty_as_malformed: bool,    // default true
    pub min_meaningful_text_len: usize,    // default 1
    pub on_truncated: TruncatedPolicy,     // default TreatAsMalformed
}

#[derive(Debug, Clone, Copy)]
pub enum TruncatedPolicy {
    TreatAsMalformed,  // 让主循环 retry
    AcceptPartial,     // 当 Final 处理
}

impl Parser {
    pub fn parse(&self, acc: &ResponseAccumulator) -> Action {
        // [1] finish_reason 异常
        match acc.finish_reason {
            Some(FinishReason::ContentFilter) => {
                return Action::Malformed { reason: "content_filter triggered".into() };
            }
            Some(FinishReason::MaxTokens) if matches!(self.config.on_truncated, TruncatedPolicy::TreatAsMalformed) => {
                return Action::Malformed { reason: "truncated by max_tokens".into() };
            }
            _ => {}
        }
        // [2] 有 tool_uses → ToolCalls
        if !acc.tool_uses.is_empty() {
            return Action::ToolCalls { calls: acc.tool_uses.clone() };
        }
        // [3] 有文本 → Final
        let text = acc.text.trim();
        if text.len() >= self.config.min_meaningful_text_len {
            return Action::Final { text: acc.text.clone() };
        }
        // [4] 啥都没有 → Malformed
        if self.config.treat_empty_as_malformed {
            Action::Malformed { reason: "empty response".into() }
        } else {
            Action::Final { text: String::new() }
        }
    }
}
```

**为什么 struct 不是 trait**:协议差异已被 ModelClient 吃掉,Parser 只看结构化数据,**多态价值 0**。

```rust
            while let Some(chunk) = inner.next().await {
                match chunk? {
                    ModelChunk::Delta(d) => {
                        buf.push_str(&d);
                        while let Some((before, tool, after)) = self.tag_parser.try_extract(&buf) {
                            if !before.is_empty() { yield Ok(ModelChunk::Delta(before)); }
                            yield Ok(ModelChunk::ToolUse {
                                call_id: format!("ulid_{}", Ulid::new()),
                                name: tool.name, args: tool.args,
                            });
                            buf = after;
                        }
                    }
                    other => yield Ok(other),
                }
            }
            if !buf.is_empty() { yield Ok(ModelChunk::Delta(buf)); }
        })
    }
}
```

M0-M1 **不实现**,留接口空间。

#### I. 流式 parse 的取舍

**不做边流边 parse**:
- text 边流边 yield `LlmStreamChunk` 已满足实时反馈
- tool_use 只在完整后才有意义,partial JSON 无法 act on
- Parser 在主循环只调一次,简单可测

例外(M3+ UI 增强):加 `ModelChunk::ToolUseProgress { call_id, partial }`,**不影响 Engine 主循环**。

### 6.4 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Adapter** | ModelClient 各 provider 适配器吃掉协议差异 | 站 4 锁定,这里发挥 |

故意**不用**:Parser trait(协议差异已下沉);流式 partial parse(无收益);完整 Visitor 模式(match 够用)。

#### A. `Tool` trait 完整定义

```rust
// src/tools/traits.rs
use async_trait::async_trait;

#[async_trait]
pub trait Tool: Send + Sync {
    // ─── 能力描述 (必填) ───
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn input_schema(&self) -> &serde_json::Value;  // JSON Schema

    // ─── 安全声明 (默认全保守,fail-closed) ───
    fn is_concurrency_safe(&self, _args: &serde_json::Value) -> bool { false }
    fn is_read_only(&self, _args: &serde_json::Value) -> bool { false }
    fn is_destructive(&self, _args: &serde_json::Value) -> bool { false }
    fn requires_user_interaction(&self) -> bool { false }
    fn default_timeout(&self) -> Option<Duration> { Some(Duration::from_secs(60)) }

    // ─── 业务校验 (Schema 之外) ───
    async fn validate_input(
        &self,
        _args: &serde_json::Value,
        _ctx: &ToolContext,
    ) -> Result<(), ToolError> { Ok(()) }

    // ─── 权限决策 ───
    async fn check_permissions(
        &self,
        args: &serde_json::Value,
        ctx: &ToolContext,
    ) -> PermissionDecision {
        default_permission_check(self, args, ctx).await
    }

    // ─── 真正执行 ───
    async fn call(
        &self,
        args: serde_json::Value,
        ctx: &ToolContext,
    ) -> Result<ToolSuccess, ToolError>;

    // ─── UI 描述 (有默认实现) ───
    fn render_use_message(&self, args: &serde_json::Value) -> String {
        format!("{}({})", self.name(), serde_json::to_string(args).unwrap_or_default())
    }
    fn render_result_message(&self, success: &ToolSuccess) -> String {
        success.summary.clone()
    }
}

#[derive(Debug, Clone)]
pub struct ToolSuccess {
    pub output: serde_json::Value,    // 结构化输出(给 LLM)
    pub summary: String,              // 一行人类可读摘要(给 UI)
    pub affected_paths: Vec<PathBuf>, // 显式声明改了哪些路径
}

#[derive(Debug, Clone)]
pub enum PermissionDecision {
    Allow,
    Deny { reason: String },
    Ask { prompt: String },
}
```

**Fail-Closed 默认值的具体落地**:
- `is_concurrency_safe = false` → M2+ 并发分批默认不并发
- `is_read_only = false` → 默认按动了文件对待
- `is_destructive = false` → **反 Claude Code 默认 false**,大多数工具不破坏,destructive 显式声明
- `default_timeout = 60s` → 防卡死

#### C. 8 步 Pipeline

```rust
// src/core/executor.rs

pub struct Executor {
    tools: Arc<ToolRegistry>,
    hooks: Arc<HookRegistry>,
    workspace: Arc<Workspace>,
    state_store: Arc<dyn StateStore>,
    approval: ApprovalPolicy,
}

impl Executor {
    pub async fn run_tool(
        &self,
        call: ToolUseRecord,
        run_id: RunId,
    ) -> Result<ToolSuccess, ToolError> {
        let span = tracing::info_span!("tool_call", name = %call.name, call_id = %call.call_id);
        let _enter = span.enter();

        // ─── [1] 工具查表 ───
        let tool = self.tools.lookup(&call.name)
            .ok_or_else(|| ToolError::UnknownTool { name: call.name.clone() })?;

        // ─── [2] Schema 校验 ───
        validate_against_schema(&call.args, tool.input_schema())
            .map_err(|e| ToolError::InvalidArgs { detail: e.to_string() })?;

        // ─── [3] 构造 ToolContext ───
        let ctx = ToolContext { /* ... */ };

        // ─── [4] Input 业务校验 ───
        tool.validate_input(&call.args, &ctx).await?;

        // ─── [5] Pre-tool hooks (M0/M1 空) ───
        let final_args = self.run_pre_hooks(&call.name, call.args, &ctx).await?;

        // ─── [6] Permission gate ───
        match tool.check_permissions(&final_args, &ctx).await {
            PermissionDecision::Allow => {}
            PermissionDecision::Deny { reason } => {
                return Err(ToolError::PermissionDenied { reason });
            }
            PermissionDecision::Ask { prompt } => {
                let approved = self.request_approval(&call.call_id, &prompt).await?;
                if !approved {
                    return Err(ToolError::PermissionDenied { reason: "user denied".into() });
                }
            }
        }

        // ─── [7] 执行 + timeout ───
        let timeout = tool.default_timeout().unwrap_or(Duration::from_secs(300));
        let exec_future = tool.call(final_args, &ctx);
        let result = tokio::select! {
            biased;
            _ = ctx.cancel.cancelled() => Err(ToolError::Cancelled),
            r = tokio::time::timeout(timeout, exec_future) => match r {
                Ok(Ok(success)) => Ok(success),
                Ok(Err(e)) => Err(e),
                Err(_) => Err(ToolError::Timeout { timeout_secs: timeout.as_secs() }),
            }
        };

        // ─── [8] Post-tool hooks (即使失败也跑) ───
        self.run_post_hooks(&call.name, &result, &ctx).await;

        result
    }
}
```

**与 Claude Code 6 步对照**:rove 8 步多了"显式 ToolContext 构造"和"Post-tool hook"。Backfill 合并进 `validate_input`。

#### E. Permission / Approval 流程

**M0/M1 同步 stdin readline**:

```rust
async fn request_approval(&self, call_id: &str, prompt: &str) -> Result<bool, ToolError> {
    match self.approval {
        ApprovalPolicy::Auto => Ok(true),
        ApprovalPolicy::Never => Ok(false),
        ApprovalPolicy::Ask => {
            eprintln!("\n[approval needed] {prompt}");
            eprint!("approve? (y/N): ");
            let mut input = String::new();
            std::io::stdin().read_line(&mut input).map_err(|e| ToolError::Execution {
                detail: format!("stdin read failed: {e}"), recoverable: false,
            })?;
            Ok(input.trim().eq_ignore_ascii_case("y"))
        }
    }
}
```

**M3+ 异步 channel**:
- Engine 持有 `Arc<DashMap<String, oneshot::Sender<bool>>>`
- yield `StreamEvent::ToolCallApprovalNeeded`
- 创建 oneshot,sender 存进 map,await receiver
- 接口层通过 `engine.approve(call_id, decision)` 取出 sender

M0/M1 直接 stdin 避免 channel 复杂度,M3+ Web 时升级。

#### G. 并发分批(M2+ 实装)

```rust
#[derive(Debug)]
pub enum ToolBatch {
    Concurrent(Vec<ToolUseRecord>),
    Sequential(ToolUseRecord),
}

impl Executor {
    pub fn partition(&self, calls: Vec<ToolUseRecord>) -> Vec<ToolBatch> {
        let mut batches = Vec::new();
        let mut current_concurrent: Vec<ToolUseRecord> = Vec::new();
        for call in calls {
            let safe = self.tools.lookup(&call.name)
                .map(|t| t.is_concurrency_safe(&call.args))
                .unwrap_or(false);
            if safe {
                current_concurrent.push(call);
            } else {
                if !current_concurrent.is_empty() {
                    batches.push(ToolBatch::Concurrent(std::mem::take(&mut current_concurrent)));
                }
                batches.push(ToolBatch::Sequential(call));
            }
        }
        if !current_concurrent.is_empty() {
            batches.push(ToolBatch::Concurrent(current_concurrent));
        }
        batches
    }
}
```

**关键**:**顺序敏感分批**(Claude Code 启示 6),`[R,R,W,R]` → `[RR],[W],[R]` 三批,不是 `[RRR],[W]`(防止 LLM 依赖 Write 副作用而第 4 个 R 在 W 之前被并发跑了)。

#### H. `affected_paths` 跟踪

**显式声明,不做 workspace 全量 diff**:
- 工具在 `ToolSuccess.affected_paths` 显式返回
- `write_file` → `[path]`,`patch_file` → `[path]`,`read_file` → `[]`,`run_shell` → 工具自行判断

**为什么不全量 diff**:
- 大 workspace 扫一次几百 ms,**累积巨大**
- 工具最清楚自己改了什么
- 真要审计靠 trace 重放

```rust
    fn description(&self) -> &str { "Ask the user for input mid-task" }
    fn input_schema(&self) -> &serde_json::Value { /* { prompt: string } */ }

        let answer = ctx.request_user_input(prompt).await?;
```

### 7.4 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Template Method** | 8 步 pipeline 骨架固定 | 主流程不变,扩展点清晰 |
| **Strategy** | `PermissionDecision` 三态 | 决策算法可换 |
| **Chain of Responsibility** | Pre-hooks 链式 | M2+ 实装 |
| **Decorator** | Hook 装饰 Tool 调用 | 不动 Tool 实现添加横切关注 |
| **Fail-Closed Defaults** | trait default 全保守 | 安全是默认,不是选项 |
| **Registry + Factory** | `ToolRegistry::with_builtins()` | 启动一次性装配 |
| **Newtype (Context)** | `ToolContext` 不是裸 args | 类型保护 + 集中 API |
| **Iterator-like Partition** | 顺序敏感分批 | Claude Code 验证 |
| **Bridge** | `Tool` trait + impl + MCP proxy 同 trait | M4 MCP 工具透明接入 |

故意**不用**:Singleton Tool(工具无状态);AbstractFactory(一个 trait 够);完整 Observer(post-hook 简化版即可)。

### 8.3 rove 设计

#### A. 三层架构

```text
Layer 1: Working Memory  (内存,本 Run)
  - history (Vec<Message>)
  - task_state
  - recent_tool_calls (M2+)

Layer 2: Session Memory  (文件,跨 Run 同 session)
  - .rove/sessions/<session_id>.json
  - summary, recent_files, completed_jobs, active_job

Layer 3: Durable Memory  (文件,跨 session)
  - .rove/memory/MEMORY.md (索引,硬限 25KB)
  - .rove/memory/topics/*.md
  - 4 种 type: user/feedback/project/reference
```

**对照 Claude Code 简化**:skip Team Memory,Auto+Agent Memory 合并(单 agent),保留 Session Memory 中间层。

#### F. `observe_step` 行为

**M0/M1 简化**:

```rust
async fn observe_step(...) -> Result<(), MemoryError> {
    // [1] 提取本轮新涉及文件路径
    let new_paths = extract_recent_files_from_history(history, step);
    
    // [2] 更新 session.recent_files (LRU 上限 20)
    if !new_paths.is_empty() {
        self.append_session_recent_files(session_id, &new_paths).await?;
    }
    
    // M0/M1 不自动写 durable memory
    Ok(())
}
```

**M2+ 升级**:
```rust
async fn observe_step(...) -> Result<(), MemoryError> {
    self.append_session_recent_files(session_id, &new_paths).await?;
    
    // 检测 memory trigger 模式,异步队列
    if detect_memory_trigger(history.last_user_message()) {
        self.promotion_queue.push(PromotionRequest { /* ... */ });
    }
    Ok(())
}
```

**关键**:`observe_step` **永远不能慢主循环**。重操作推到异步队列或后置 hook。

**Session summary 触发**(借鉴 Claude Code 启示 6):

```rust
pub struct SessionSummaryPolicy {
    pub min_tokens_to_init: u32,           // default 10_000
    pub min_tokens_between_update: u32,    // default 5_000
    pub tool_calls_between_updates: u32,   // default 3
}

pub fn should_extract_session_summary(
    history: &History,
    last_extracted_step: u32,
    current_step: u32,
    counter: &TokenCounter,
    policy: &SessionSummaryPolicy,
) -> bool {
    let tokens = counter.count_messages(history.messages());
    if !is_initialized() && tokens < policy.min_tokens_to_init { return false; }
    
    let tokens_ok = tokens >= policy.min_tokens_between_update;
    let tool_calls_ok = count_tool_calls_since(last_extracted_step, current_step) >= policy.tool_calls_between_updates;
    let no_pending_tool_use = !has_pending_tool_use_in_last_turn(history);
    
    // token 阈值必要;自然断点 OR 双阈值满足
    tokens_ok && (tool_calls_ok || no_pending_tool_use)
}
```

**关键**:`!has_pending_tool_use_in_last_turn` 找自然断点,**避免在 tool_use/tool_result 链中间截断**。

#### H. Durable memory 写入

**M0/M1**:用户手动维护(直接编辑 `.rove/memory/` 文件),rove **只读不写**。

**M2+**:LLM 通过 `save_memory` tool 写:

```rust
pub struct SaveMemoryTool;

#[async_trait]
impl Tool for SaveMemoryTool {
    fn name(&self) -> &str { "save_memory" }
    fn description(&self) -> &str {
        "Save a durable memory entry. Use only for facts/preferences that should persist across sessions."
    }
    // schema: { topic: string, content: string, type: user|feedback|project|reference }
    
    async fn call(&self, args: serde_json::Value, ctx: &ToolContext) -> Result<ToolSuccess, ToolError> {
        let topic = args["topic"].as_str().ok_or(...)?;
        let content = args["content"].as_str().ok_or(...)?;
        let mem_type: MemoryType = serde_json::from_value(args["type"].clone())?;
        
        ctx.memory.save_durable_topic(topic, content, /* TopicMetadata */).await?;
        ctx.memory.update_memory_index().await?;
        
        Ok(ToolSuccess {
            output: json!({ "saved": true, "topic": topic }),
            summary: format!("saved memory: {}", topic),
            affected_paths: vec![
                format!(".rove/memory/topics/{}.md", topic).into(),
                ".rove/memory/MEMORY.md".into(),
            ],
        })
    }
}
```

**Promotion gate**:不是 rove 替 LLM 决定 —— **LLM 决定**,rove 提供工具 + system prompt 告诉它 "what to save / what NOT to save"。

System prompt 加入(M2+):

```markdown
## When to save durable memory

SAVE: user preferences, project decisions, external system pointers, workflow corrections from user
DO NOT SAVE: code patterns (derivable), git history, debug fixes, content in docs, ephemeral task details
```

#### I. Relevant retrieval(M3+ 占位)

```rust
async fn retrieve_relevant(&self, query: &str, limit: usize) -> Result<Vec<MemorySnippet>, MemoryError> {
    if !self.config.feature_flags.relevant_memory_enabled {
        return Ok(Vec::new()); // M0-M2 默认关
    }
    
    match self.config.memory.retrieval_strategy {
        RetrievalStrategy::LightweightLLM => self.retrieve_via_side_query(query, limit).await,
        RetrievalStrategy::Vector => self.retrieve_via_vector(query, limit).await,
    }
}
```

**两策略对比**:

| 维度 | LightweightLLM | Vector |
|---|---|---|
| 实现复杂度 | 中 | 高 |
| 延迟 | ~500ms | ~10ms |
| 成本 | 每次 LLM 调用 | embedding 一次性 |
| 准确度 | 看 metadata 质量 | 看 embedding 质量 |

**M3 选 Vector**(lancedb 已为 RAG 引入,增量成本低)。

#### J. Memory operations as tools(M2+)

| Tool | 干嘛 | 启用 milestone |
|---|---|---|
| `save_memory(topic, content, type)` | 写新 topic | M2+ |
| `update_memory_index()` | 重建 MEMORY.md | M2+ |
| `read_memory_topic(name)` | 读 topic 全文 | M2+ |

**为什么 `read_memory_topic` 单独立而不是 `read_file`**:
- 安全:限定 `.rove/memory/topics/`,防止用 read_file 探别处
- 可统计:trace 里计入 memory 访问指标
- 可治理:M3+ 加 cache

### 8.4 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Layered Architecture** | 3 层 memory 边界 | 不同生命周期 / 写策略 |
| **Repository Pattern** | `MemoryStore` trait + impl | 实现可换 |
| **Lazy Loading** | DurableMemoryDump 默认只 metadata | 不爆 prompt |
| **Write-Behind Queue** | M2+ promotion 异步 | 不阻塞主循环 |
| **Hard Cap + Truncation** | MEMORY.md 200 line / 25KB | Claude Code 验证 |
| **Frontmatter Schema** | topic frontmatter | 结构化但人类可读 |
| **Sync IO at Prompt Build** | `read_memory_index_sync()` | 工程务实 |
| **Type-tagged Memory** | 4 种 enum | 不同写入策略 |
| **Tool-driven Updates** | Tool 写 memory,不是 Engine 内部 | 启示 10 |

故意**不用**:Team Memory / Sync(单人);Snapshot(M7+);Multi-scope(M7+);versioning(用 git);加密(用 gpg)。

#### C. `trace.jsonl` 事件格式

JSONL,一行一 JSON,扁平 schema,可 `tail -f`:

```json
{"ts":"2026-05-17T09:00:00.123Z","run_id":"01HX","step":0,"type":"run_started","data":{"user_message":"foo","job_id":"01HX"}}
{"ts":"2026-05-17T09:00:00.456Z","run_id":"01HX","step":1,"type":"llm_call_started","data":{"prompt_tokens_estimated":1234}}
```

```rust
// src/state/trace.rs
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct TraceEvent {
    pub ts: DateTime<Utc>,
    pub run_id: RunId,
    pub step: u32,
    #[serde(flatten)]
    pub payload: TraceEventPayload,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum TraceEventPayload {
    RunStarted { user_message: String, job_id: JobId, session_id: SessionId },
    LlmCallStarted { prompt_estimated_tokens: u32, provider: ModelClientId },
    LlmMessageCompleted { full_text: String, usage: Usage, finish_reason: FinishReason },
    ToolCallStarted { call_id: String, name: String, args: serde_json::Value },
    ToolCallCompleted { call_id: String, affected_paths: Vec<PathBuf>, output_summary: String },
    ToolCallFailed { call_id: String, error_code: String, error_message: String },
    ToolCallApprovalNeeded { call_id: String, prompt: String },
    ContextCompacted { before_tokens: u32, after_tokens: u32 },
    MemoryWritten { topic: String, summary: String },
    StepCompleted { usage_after: Usage },
    RunCompleted { reason: TerminationReason, final_output: Option<String> },
}
```

**关键决策**:
- **不 trace 每个 `LlmStreamChunk`**(数据量爆炸),只 trace `LlmMessageCompleted` 完整文本
- 调试需要时 env `ROVE_TRACE_CHUNKS=1` 开启
- `full_text` 超 8KB 截断,记 `truncated: true`(避免破坏 O_APPEND 原子性)

#### F. Atomic write 策略

`task_state.json` 和 `report.json` 用 **tmp + rename**:

```rust
async fn atomic_write(path: &Path, content: &str) -> Result<(), StateError> {
    let tmp = path.with_extension("json.tmp");
    tokio::fs::write(&tmp, content).await?;
    tokio::fs::rename(&tmp, path).await?;
    Ok(())
}
```

**POSIX 保证 rename 同 fs 内原子**(NTFS 也是)。读者永不见半写。

`trace.jsonl` 用 **`O_APPEND`**:

```rust
async fn append_line(path: &Path, line: &str) -> Result<(), StateError> {
    use tokio::io::AsyncWriteExt;
    let mut file = tokio::fs::OpenOptions::new()
        .append(true).create(true).open(path).await?;
    file.write_all(line.as_bytes()).await?;
    file.write_all(b"\n").await?;
    file.flush().await?;
    Ok(())
}
```

**O_APPEND 原子保证**:Linux/macOS 上 < 4KB(PIPE_BUF)的 write 是 atomic。**事件 JSON 通常远小于 4KB**,但 `LlmMessageCompleted.full_text` 可能超出 → **截断到 8KB**(并不冲突,truncate 后整行 ~9KB 仍单次写,但理论上可能被 OS 拆,代价是极小概率 trace 行错位,可接受)。

#### G. Resume 机制

**M0/M1 简单 Resume**(`--resume <session_id>`):
- 加载该 session 的 working memory
- 创建**新 Job + 新 Run**,带 session context
- **不重放历史 trace**,history 从空开始
- 适合 "继续上次话题" 场景

**M2+ 完整 Resume**(`--resume <job_id>`):
- 加载该 Job 所有历史 Run 的 trace
- 重建 history(从 LlmMessageCompleted + ToolCallCompleted 事件)
- 校验 `config_snapshot` 兼容性
- 创建新 Run on 既有 Job,history 从重建结果开始
- 适合 "step_limit 命中继续干" 场景

```rust
// M2+ 实现
async fn resume_job(&self, job_id: JobId) -> Result<RunRequest, ResumeError> {
    let job = self.state_store.load_job(job_id).await?;
    let runs = self.state_store.list_runs_of_job(job_id).await?;
    let mut full_trace = Vec::new();
    for run_id in &runs {
        full_trace.extend(self.state_store.load_trace(*run_id).await?);
    }
    let history = reconstruct_history_from_trace(&full_trace)?;
    
    let last_run = self.state_store.load_run(*runs.last().unwrap()).await?;
    if last_run.config_snapshot.provider_id != self.current_provider() {
        tracing::warn!("resuming with different provider, results may differ");
    }
    
    Ok(RunRequest {
        message: job.user_message,
        session_id: Some(job.session_id),
        job_id: Some(job_id),
        overrides: RunOverrides::default(),
    })
}
```

```rust
        tokio::fs::create_dir_all(&dir).await?;
        atomic_write(&dir.join("task_state.json"),

    async fn snapshot_run(&self, run_id: RunId, snap: &TaskStateSnapshot) -> Result<(), StateError> {
        let mut state = self.load_run(run_id).await?;
        state.apply_snapshot(snap);
        atomic_write(&self.run_dir(run_id).join("task_state.json"),
                     &serde_json::to_string_pretty(&state)?).await
    }
    
    async fn append_trace_event(&self, run_id: RunId, event: &TraceEvent) -> Result<(), StateError> {
        let path = self.run_dir(run_id).join("trace.jsonl");
        append_line(&path, &serde_json::to_string(event)?).await
    }
    
    async fn finalize_run(&self, run_id: RunId, report: &Report) -> Result<(), StateError> {
        let dir = self.run_dir(run_id);
        atomic_write(&dir.join("report.json"),
                     &serde_json::to_string_pretty(report)?).await?;
        let mut state = self.load_run(run_id).await?;
        state.status = report.status;
        state.ended_at = Some(report.ended_at);
        state.termination_reason = Some(report.termination_reason.clone());
        atomic_write(&dir.join("task_state.json"),
                     &serde_json::to_string_pretty(&state)?).await
    }
}
```

### 9.4 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Event Sourcing** | trace.jsonl 是 canonical truth | resume 时可从 trace 重建 |
| **Repository Pattern** | `StateStore` trait + File/InMemory | 测试可换 |
| **Atomic Write** | tmp+rename for task_state/report | POSIX 保证 |
| **Append-Only Log** | trace.jsonl O_APPEND | 原子追加 |
| **Schema Versioning** | 每文件 `schema_version` | 向后兼容 |
| **Snapshot + Replay** | task_state = snapshot,trace = log | 数据库 WAL 同套 |
| **DTO** | `TaskStateSnapshot` vs `TaskState` | 主循环开销低 |
| **Strategy** | File vs InMemory store | 部署 vs 测试 |

故意**不用**:真正事件溯源(每步 replay 太慢);二进制格式(可观察性优于压缩);数据库(运维复杂)。

### 9.5 锁定决策

| # | 决策 | 选择 |
|---|---|---|
| 9.1 | 三件套布局 | `.rove/runs/<run_id>/{task_state.json, trace.jsonl, report.json}` |

| 9.5 | full_text 截断 | 8KB + `truncated: true` |
| 9.6 | task_state 写时机 | create / 每 step / finalize |
| 9.7 | Atomic 策略 | tmp+rename for task_state/report;O_APPEND for trace |
| 9.8 | Resume M0/M1 | session-level,不重放 trace |
| 9.9 | Resume M2+ | job-level,完整重放重建 history |

### 10.3 rove 设计

#### A. `PostRunHook` trait

**和站 7 的 PreToolHook/PostToolHook 完全不同**:
- 站 7:**单个工具调用** 前后(粒度小)
- 站 10:**整个 Run 结束** 后(粒度大)

```rust
// src/hooks/post_run.rs
#[async_trait]
pub trait PostRunHook: Send + Sync {
    fn name(&self) -> &str;
    async fn after_run(&self, ctx: &PostRunContext) -> Result<(), HookError>;
    fn should_run(&self, _ctx: &PostRunContext) -> bool { true }
    fn timeout(&self) -> Duration { Duration::from_secs(30) }
}

#[derive(Clone)]
pub struct PostRunContext {
    pub run_id: RunId,
    pub job_id: JobId,
    pub session_id: SessionId,
    pub report: Arc<Report>,
    pub trace: Arc<[TraceEvent]>,
    pub state_store: Arc<dyn StateStore>,
    pub memory_store: Arc<dyn MemoryStore>,
    pub model_client: Arc<dyn ModelClient>,
    pub config: Arc<Config>,
    pub workspace: Arc<Workspace>,
}

#[derive(Debug, thiserror::Error)]
pub enum HookError {
    #[error("hook timeout")] Timeout,
    #[error("storage error: {0}")] Storage(String),
    #[error("model error: {0}")] Model(String),
    #[error("other: {0}")] Other(String),
}
```

#### B. 触发时机 + 同步等

**关键决策**:**hooks 同步 join 完成后才关闭 stream**。

```rust
// in main_loop 末尾
yield StreamEvent::RunCompleted { /* ... */ };

let post_ctx = PostRunContext { /* ... */ };
self.deps.hooks.run_post_run_hooks(&post_ctx, cancel.clone()).await;
// stream 自然结束
```

**为什么同步等而不是 `tokio::spawn`**:
- CLI 模式:spawn 出去的 task 主进程退出时被 killed,hook 丢失
- API 模式:同步等让 HTTP response 包含完整结果(memory 已更新)
- 用户体验:RunCompleted 已 yield,hook 多花 200ms-2s 可接受
- 一致性:trace / memory / session 一定一致地落盘

**取消传播**:

```rust
async fn run_post_run_hooks(&self, ctx: &PostRunContext, cancel: CancellationToken) {
    let hooks: Vec<_> = self.post_run.iter().filter(|h| h.should_run(ctx)).collect();
    let futures = hooks.iter().map(|h| run_single_hook_isolated(Arc::clone(h), ctx.clone()));
    
    tokio::select! {
        biased;
        _ = cancel.cancelled() => tracing::warn!("post-run hooks cancelled"),
        _ = futures::future::join_all(futures) => {}
    }
}
```

#### C. 错误隔离

每 hook 单独包 timeout + catch_unwind:

```rust
async fn run_single_hook_isolated(hook: Arc<dyn PostRunHook>, ctx: PostRunContext) {
    let timeout = hook.timeout();
    let name = hook.name().to_string();
    
    let result = tokio::time::timeout(
        timeout,
        AssertUnwindSafe(hook.after_run(&ctx)).catch_unwind(),
    ).await;
    
    match result {
        Ok(Ok(Ok(()))) => tracing::debug!(hook = %name, "ok"),
        Ok(Ok(Err(e))) => tracing::warn!(hook = %name, error = ?e, "failed"),
        Ok(Err(_)) => tracing::error!(hook = %name, "panicked"),
        Err(_) => tracing::warn!(hook = %name, secs = ?timeout.as_secs(), "timeout"),
    }
}
```

**关键**:单 hook 失败 / panic / 超时**绝不影响其他 hook,更不影响 run 结果**(report 早已 finalize)。

#### G. `DurableMemoryPromotionHook` (M2+)

**LLM 决定记不记 + rove 提供工具**:

```rust
pub struct DurableMemoryPromotionHook {
    promotion_model: Option<Arc<dyn ModelClient>>,
}

#[async_trait]
impl PostRunHook for DurableMemoryPromotionHook {
    fn name(&self) -> &str { "durable_memory_promotion" }
    fn timeout(&self) -> Duration { Duration::from_secs(30) }
    
    fn should_run(&self, ctx: &PostRunContext) -> bool {
        ctx.report.status == RunStatus::Done
            && matches!(ctx.report.termination_reason, TerminationReason::Final)
    }
    
    async fn after_run(&self, ctx: &PostRunContext) -> Result<(), HookError> {
        // [1] 正则检测 trigger 模式
        let last_user_msg = extract_last_user_message(&ctx.trace);
        let triggers = detect_memory_triggers(&last_user_msg);
        if triggers.is_empty() { return Ok(()); }
        
        // [2] 调小 LLM 提取 memorable facts(ragent utility 参数)
        let prompt = build_promotion_prompt(&triggers, &ctx.trace);
        let model = self.promotion_model.as_ref().unwrap_or(&ctx.model_client);
        let response = model.complete(&ModelRequest {
            system: PROMOTION_SYSTEM_PROMPT.to_string(),
            messages: vec![Message::user(&prompt)],
            temperature: 0.1, top_p: 0.3, thinking: false, max_tokens: 2048,
        }).await.map_err(|e| HookError::Model(e.to_string()))?;
        
        // [3] parse 出 JSON
        let entries: Vec<MemorablEntry> = serde_json::from_str(&response.text)
            .map_err(|e| HookError::Other(format!("parse failed: {e}")))?;
        
        // [4] 写入 durable
        for entry in &entries {
            ctx.memory_store.save_durable_topic(&entry.topic, &entry.content, entry.metadata.clone()).await
                .map_err(|e| HookError::Storage(e.to_string()))?;
        }
        ctx.memory_store.update_memory_index().await
            .map_err(|e| HookError::Storage(e.to_string()))?;
        
        tracing::info!(promoted = entries.len(), "durable memory promoted");
        Ok(())
    }
}

fn detect_memory_triggers(msg: &str) -> Vec<MemoryTrigger> {
    let mut triggers = Vec::new();
    let lower = msg.to_lowercase();
    if lower.contains("remember") || msg.contains("记住") { triggers.push(MemoryTrigger::Remember); }
    if lower.contains("from now on") || msg.contains("以后都") { triggers.push(MemoryTrigger::Always); }
    if lower.contains("i prefer") || msg.contains("我喜欢") || msg.contains("不要") { triggers.push(MemoryTrigger::Preference); }
    triggers
}
```

**三层 gate 成本控制**:正则触发(零成本)→ LLM 决策(中成本)→ save tool 执行(低成本)。**大多数 run 早期出口**。

`ShellHook` 是个内部实现,把 config 里的 shell 命令包成 `PostRunHook`,M3+ 实装。

### 10.4 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Observer** | hooks 观察 RunCompleted | 解耦,核心 run 不感知 hook |
| **Strategy** | `should_run` 决定执行 | 不是所有 hook 总要跑 |
| **Error Isolation Container** | timeout + catch_unwind | 单 hook 不拖垮 |
| **Template Method** | `after_run` 模板 | 各 hook 内部自由 |
| **Composite** | `join_all` 并行 | 所有 hook 聚合 |
| **Three-tier Gate** | 正则 → LLM → save tool | 成本逐级递增 |

故意**不用**:hooks 依赖排序(合并成一个);Cross-run hook(外部 cron);动态加载(不在路线图)。

### 10.5 锁定决策

| # | 决策 | 选择 |
|---|---|---|
| 10.1 | 触发时机 | RunCompleted yield 之后,stream 关闭之前 |
| 10.2 | 等不等 hooks | **等**(blocks stream close) |
| 10.3 | hooks 并行 | 是,`join_all` |
| 10.4 | 单 hook 失败 | log warning |
| 10.5 | 单 hook panic | log error (catch_unwind) |
| 10.6 | 单 hook 超时 | default 30s,可 override |
| 10.7 | 取消传播 | 共享 CancellationToken |
| 10.8 | M0 builtins | TraceFlushHook / JobFinalizeHook / SessionUpdateHook |
| 10.9 | M1 builtins | + MetricsHook |
| 10.10 | M2+ builtins | + SessionCompactCheckHook / DurableMemoryPromotionHook |
| 10.11 | 用户自定义 | M3+ 通过 config.toml(ShellHook) |
| 10.12 | hook 调 LLM | 是,通过 ctx.model_client(可单独配 utility model) |
| 10.13 | Promotion 三层 gate | 正则触发 → LLM 决策 → save tool |

### 10.6 显式不做

- Hook plugin 动态加载(dlopen / wasm)→ 不在路线图
- Hook 之间依赖排序 → 合并成一个 hook
- Cross-run / Cross-session hook → 外部 cron

```rust
    verbosity: Verbosity,
    use_color: bool,
    is_tty: bool,
    spinner_active: Option<indicatif::ProgressBar>,

#[derive(Debug, Clone, Copy, PartialOrd, Ord, PartialEq, Eq)]
pub enum Verbosity {
    Quiet,    // 只输出 final + 错误
    Normal,   // + 工具调用名
    Verbose,  // + thinking + 完整 args + step
    Debug,    // + 所有事件 JSON
}

impl TerminalRenderer {
    pub fn from_cli(cli: &Cli) -> Self {
        let is_tty = atty::is(atty::Stream::Stdout);
        let use_color = is_tty
            && std::env::var("NO_COLOR").is_err()
            && std::env::var("CLICOLOR").map(|v| v != "0").unwrap_or(true);
        Self { /* ... */ }
    }
    
    pub fn render(&mut self, event: &StreamEvent) {
        match event {
            StreamEvent::LlmStreamChunk { delta, .. } => {
                print!("{delta}");
                let _ = io::stdout().flush();
            }
            StreamEvent::ToolCallStarted { name, args, .. } => {
                if self.verbosity >= Verbosity::Normal {
                    self.eprint_tag("tool", "cyan",
                        &format!("→ {name}({})", summarize_args(args, 80)));
                    self.start_spinner(name);
                }
            }
            StreamEvent::ToolCallCompleted { output_summary, .. } => {
                self.stop_spinner();
                if self.verbosity >= Verbosity::Normal {
                    self.eprint_tag("done", "green", output_summary);
                }
            }
            StreamEvent::ToolCallFailed { error_code, error_message, .. } => {
                self.stop_spinner();
                self.eprint_tag("error", "red", &format!("{error_code}: {error_message}"));
            }
            StreamEvent::RunCompleted { reason, usage, .. } => {
                self.stop_spinner();
                if self.verbosity >= Verbosity::Normal {
                    self.print_run_summary(reason, usage);
                }
            }
            _ => if self.verbosity == Verbosity::Debug {
                let _ = writeln!(io::stderr(), "{}", serde_json::to_string(event).unwrap_or_default());
            }
        }
    }
}
```

```rust
async fn handle_slash_command(line: &str, engine: &Engine, session_id: &mut Option<SessionId>) -> anyhow::Result<()> {
    let parts: Vec<&str> = line[1..].split_whitespace().collect();
    let cmd = parts.first().copied().unwrap_or("");
    match cmd {
        "help" | "h" | "?" => print_help(),
        "exit" | "quit" | "q" => std::process::exit(0),
        "session" => {
            if let Some(id) = session_id {
                let s = engine.deps.memory.resolve_session(*id).await?;
                println!("{}", serde_json::to_string_pretty(&s)?);
            }
        }
        "reset" => { *session_id = None; println!("session reset"); }
        "memory" => {
            let idx = engine.deps.memory.read_memory_index_sync()?;
            println!("{idx}");
        }
        "history" => {
            if let Some(id) = session_id {
                let jobs = engine.deps.state_store.list_resumable_jobs(*id).await?;
                for j in jobs { println!("  {j:?}"); }
            }
        }
        _ => println!("unknown: /{cmd} (try /help)"),
    }
    Ok(())
}
```

#### H. `JobBroker` 多 subscriber

```rust
// src/interfaces/api/broker.rs
pub struct JobBroker {
    jobs: DashMap<JobId, broadcast::Sender<StreamEvent>>,
}

impl JobBroker {
    pub async fn register(&self, job_id: JobId, mut stream: Pin<Box<dyn Stream<Item = StreamEvent> + Send>>) {
        let (tx, _) = broadcast::channel::<StreamEvent>(256);
        self.jobs.insert(job_id, tx.clone());
        tokio::spawn(async move {
            while let Some(event) = stream.next().await {
                let _ = tx.send(event);  // 没 subscriber 也不报错
            }
        });
    }
    
    pub async fn subscribe(&self, job_id: JobId) -> impl Stream<Item = StreamEvent> {
        let tx = self.jobs.get(&job_id).map(|e| e.value().clone());
        match tx {
            Some(tx) => BroadcastStream::new(tx.subscribe()).filter_map(|r| async move { r.ok() }),
            None => /* 404 */,
        }
    }
}
```

**`broadcast::channel` 解决多 subscriber 问题** —— 同一 job 可在多 HTTP 连接订阅(用户刷新页面)。

```rust
// src/main.rs
async fn install_signal_handler(
    app_cancel: CancellationToken,
    signal_reason: Arc<Mutex<Option<SignalReason>>>,
) {
    let sigint = async {
        if tokio::signal::ctrl_c().await.is_ok() {
            tracing::info!("received SIGINT");
            *signal_reason.lock().await = Some(SignalReason::Sigint);
            app_cancel.cancel();
        }
    };

    let sigterm = async {
        let mut s = tokio::signal::unix::signal(
            tokio::signal::unix::SignalKind::terminate()
        ).unwrap();
        s.recv().await;
        tracing::info!("received SIGTERM");
        *signal_reason.lock().await = Some(SignalReason::Sigterm);
        app_cancel.cancel();
    };
    #[cfg(not(unix))]
    let sigterm = std::future::pending::<()>();
    
    tokio::select! {
        _ = sigint => {}
        _ = sigterm => {}
    }
}
```

#### C. 优雅退出顺序(Oneshot 模式)

```text
SIGINT/SIGTERM
  → app_cancel.cancel()
  → run_cancel (child) 同时 cancel
  → 主循环在最近 cancel check 点 yield RunCompleted(Cancelled)
  → state_store.finalize_run(status=Cancelled)
  → post-run hooks 跑(每个 hook 也响应 cancel + timeout)
       ├ TraceFlushHook ✓
       ├ JobFinalizeHook ✓
       ├ SessionUpdateHook ✓
       └ MetricsHook / DurableMemoryPromotion 可能被 cancel
  → stream 结束 (None)
  → Renderer return
  → async_main return
  → runtime drop → 等所有 spawned task
  → main() return ExitCode::from(130 or 143)
```

**关键**:Run 完成(包括 cancel 路径)和 hooks 完成都在 stream 结束前发生。这是站 10 "同步等 hooks" 决策的延伸。

#### D. REPL 模式 Ctrl+C 不同行为

REPL 两个状态:**等 prompt** 和 **跑 run**。

| 状态 | Ctrl+C 行为 |
|---|---|
| 等 prompt(rustyline readline) | rustyline 返回 `Interrupted`,**continue 不退出** |
| 跑 run 期间 | 只取消当前 run,**REPL 继续**(独立 ctrl_c task) |

```rust
// src/interfaces/cli/repl.rs (修订)
loop {
    match rl.readline("rove> ") {
        Ok(line) => {

            let run_cancel = engine.deps.app_cancel.child_token();
            let mut stream = engine.run_with_cancel(req, run_cancel.clone());
            
            let ctrl_c_task = tokio::spawn({
                let cancel = run_cancel.clone();
                async move {
                    let _ = tokio::signal::ctrl_c().await;
                    cancel.cancel();
                }
            });
            
            while let Some(event) = stream.next().await {
                renderer.render(&event);
            }
            
            ctrl_c_task.abort();  // run 完成,关闭监听
        }

        Err(rustyline::error::ReadlineError::Eof) => break,
        Err(e) => return Err(e.into()),
    }
}
```

**关键设计**:REPL 在每个 run 期间手动起 ctrl_c task,**只 cancel 当前 run**,不传染 app_cancel。SIGTERM 走 app_cancel(退 REPL)。

#### F. Exit code 约定

```rust
#[derive(Debug)]
enum ExitOutcome {
    Final,
    LimitHit,
    RunError,
    CancelledSigint,
    CancelledSigterm,
    SetupError,
    Panic,
}

impl ExitOutcome {
    fn to_exit_code(self) -> std::process::ExitCode {
        use std::process::ExitCode;
        match self {
            Self::Final => ExitCode::SUCCESS,             // 0
            Self::Panic => ExitCode::from(1),             //   1
            Self::LimitHit => ExitCode::from(3),          //   3
            Self::RunError => ExitCode::from(4),          //   4
            Self::SetupError => ExitCode::from(5),        //   5
            Self::CancelledSigint => ExitCode::from(130), // 130 (128+SIGINT)
            Self::CancelledSigterm => ExitCode::from(143),// 143 (128+SIGTERM)
        }
    }
}
```

**为什么 130/143**:Unix 约定 `128 + signal_number`,bash `$?` 检查时友好。

#### G. Panic hook

```rust
fn install_panic_hook() {
    let default = std::panic::take_hook();
    std::panic::set_hook(Box::new(move |info| {
        let bt = std::backtrace::Backtrace::force_capture();
        tracing::error!(panic = %info, backtrace = %bt, "PANIC");
        
        // best-effort 写到当前 run 的 trace
        if let Some(run_id) = current_run_id::get() {
            let _ = write_panic_to_trace(run_id, &info.to_string(), &bt.to_string());
        }
        
        default(info);
    }));
}

thread_local! {
    static CURRENT_RUN_ID: RefCell<Option<RunId>> = RefCell::new(None);
}
```

**关键**:panic hook **best-effort 写 trace**,失败也不抛(panic 已经是失败路径,二次失败不该 propagate)。

#### H. 完整 main() 骨架

```rust
fn main() -> std::process::ExitCode {
    install_panic_hook();
    
    let cli = match Cli::try_parse() {
        Ok(c) => c,
        Err(e) => { eprintln!("{e}"); return ExitCode::from(5); }
    };
    init_tracing(&cli);
    
    // Fast path (站 1)
    match &cli.command {
        Some(SubCommand::DumpConfig) => { /* ... */ return ExitCode::SUCCESS; }
        Some(SubCommand::Sessions) => { /* ... */ return ExitCode::SUCCESS; }
        _ => {}
    }
    
    // Full path
    let rt = match tokio::runtime::Builder::new_multi_thread().enable_all().build() {
        Ok(rt) => rt,
        Err(_) => return ExitCode::from(5),
    };
    
    let app_cancel = CancellationToken::new();
    let signal_reason = Arc::new(Mutex::new(None));
    
    rt.spawn(install_signal_handler(app_cancel.clone(), Arc::clone(&signal_reason)));
    
    let outcome = rt.block_on(async_main(cli, app_cancel.clone()));
    
    drop(rt);  // 等所有 spawned task
    
    let signal = signal_reason.blocking_lock().clone();
    let final_outcome = match (outcome, signal) {
        (_, Some(SignalReason::Sigint)) => ExitOutcome::CancelledSigint,
        (_, Some(SignalReason::Sigterm)) => ExitOutcome::CancelledSigterm,
        (Ok(o), None) => o,
        (Err(_), None) => ExitOutcome::SetupError,
    };
    
    final_outcome.to_exit_code()
}
```

#### I. 资源清理 RAII 链

```text
async_main 返回
  └─ Engine 离开作用域,Drop
       └─ EngineDeps Drop
            ├─ Arc<Workspace> refcount-- (可能 release)
            ├─ Arc<dyn StateStore> refcount-- (release → close files)
            ├─ Arc<dyn ModelClient> refcount-- (release → close reqwest conns)
            ├─ Arc<dyn MemoryStore> refcount--
            └─ Arc<HookRegistry> refcount--

rt.drop()
  └─ 取消所有 spawned task
  └─ join 完成
  └─ 释放 worker threads

main() return ExitCode
```

**M0/M1**:RAII 自然完成所有清理。
**M2+(open trace 句柄优化)**:`FileStateStore::drop` 显式 close 所有 BufWriter。

### 12.4 设计模式

| 模式 | 体现 | 为什么 |
|---|---|---|
| **Graceful Shutdown** | signal → cancel → drain → exit | 不丢数据 |
| **Token Tree** | app_cancel + child_token() | 一次取消多层传播 |
| **Hook (panic_hook)** | `std::panic::set_hook` | 全局兜底 |
| **Exit Code Mapping** | outcome → process code | bash / CI 友好 |
| **RAII** | Drop 链自动释放 | Rust 习语 |
| **Differential Cancellation** | REPL 内 Ctrl+C 只 cancel run | 用户体验 |
| **Drain Pattern** | API shutdown 等 in-flight | M5 |

故意**不用**:强制 kill;Process group;Atexit 钩子(用 Drop);Crash dump(RUST_BACKTRACE 够);重启策略(外部 supervisor)。

### 12.5 锁定决策

| # | 决策 | 选择 |
|---|---|---|
| 12.1 | Cancel token 层级 | app_cancel + run_cancel (child) |
| 12.2 | EngineDeps 加 app_cancel | ✅(patch 站 1) |
| 12.3 | Signal 监听 | tokio::signal + Unix SIGTERM |
| 12.4 | Exit code | 0/1/3/4/5/130/143 |
| 12.5 | Panic hook | `set_hook` + best-effort 写 trace |
| 12.6 | REPL Ctrl+C 在 prompt | 不退出,清空 buffer |
| 12.7 | REPL Ctrl+C 在 run | 只 cancel run,不退 REPL |
| 12.8 | REPL Ctrl+D | 退出 REPL |
| 12.9 | REPL SIGTERM | 退出 REPL |
| 12.10 | Oneshot SIGINT | cancel → 等清理 → exit 130 |
| 12.11 | API shutdown | axum graceful + JobBroker drain |
| 12.12 | tokio runtime drop | block 等 spawned task |
| 12.13 | M0/M1 文件清理 | RAII 自然完成 |
| 12.14 | M2+ 文件句柄优化 | drop 时显式 close BufWriter |
| 12.15 | 测试覆盖 | 10 个退出路径全测 |

### 12.6 显式不做

- 强制 kill / 立即退出 → 总是 graceful
- 子进程 process group 管理 → 工具自管
- Atexit 钩子 → Drop trait
- Crash dump 生成 → RUST_BACKTRACE + panic_hook 够
- 重启策略(systemd-style)→ 外部 supervisor
