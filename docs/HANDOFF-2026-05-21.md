# rove Handoff - 2026-05-21

## Current Position

rove is being built as a local-first, stateful, observable agent runtime.

The current strategy is:

1. Finish M0-M2 as the execution kernel.
2. Do not treat M0-M2 as the final product.
3. After M2, build a more distinctive product layer around replay, observability, artifacts, and workspace-level workflows.

We explicitly decided not to chase any single ByteDance challenge topic. The contest list was only used as reference for market context.

Current implementation boundary: this repo is at the M0 baseline. M1 and M2 are planned next and have not been implemented yet.

## Development Order

### M0: Minimal Runtime Closure

Goal: make the project compile, run locally, detect workspace, stream events, and write trace/report artifacts.

Current M0 status:

- Rust toolchain updated to stable `1.95.0`.
- Parent `agent/docs` content copied into this repo under `docs/`.
- `src/main.rs` now consumes the library crate via `use rove::...`.
- This means the binary imports the library crate, instead of redeclaring modules locally. Keep this shape.
- CLI binary is now a thin shell over the library modules.
- `FakeModelClient` added at `src/models/fake.rs`.
- `ROVE_MODEL=fake cargo run -- "<task>"` works without an API key.
- `.rove/runs/<run_id>/trace.jsonl` and `report.json` are generated.
- Run identity mismatch was fixed: run directory, `trace.jsonl`, and `report.json` now use the same `run_id`.
- `.rove/` is ignored and not committed.

Verified commands:

```powershell
cargo fmt --all
cargo clippy --all-targets --all-features -- -D warnings
cargo test
$env:ROVE_MODEL='fake'; cargo run -- "hello m0 identity"
```

### M1: Stateful Tools and Resume

Next target after this handoff:

- Add `ToolContext` and approval policy.
- Add a real tool boundary module.
- Make destructive tools explicitly blocked under `ApprovalPolicy::Never`.
- Add `task_state.json`.
- Add `--resume latest`.
- Persist and restore basic history/summary state.
- Tighten `ContextManager` so it accepts memory sections and deterministic history trimming.

Do not start RAG, MCP, API, Web UI, or multi-agent before M1 is stable.

### M2: Planner

After M1:

- Add `prompts/planner.md`.
- Add `TaskPlan` and `PlanStep`.
- Add `src/core/planner.rs`.
- Persist plan state in `task_state.json`.
- Let interrupted runs resume at the correct plan step.
- Keep the planner lightweight. It is a task organizer, not a separate agent system yet.

## Important Architecture Decisions

- `core` is the library.
- `interfaces/cli` is only a shell.
- `src/main.rs` should use `rove::...`, not local `mod core; mod tools;`.
- Workspace is the product boundary.
- Repo is only one `WorkspaceKind`, not the whole product.
- M0-M2 may look like Claude Code at the surface. That is acceptable because they are the engine, not the final differentiation.
- Differentiation should come after M2 through replay, observability, artifacts, run comparison, workspace memory, and workbench-style product features.
