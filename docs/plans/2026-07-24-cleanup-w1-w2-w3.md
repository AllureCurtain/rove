## Worktree workflow (mandatory)

### Why

- Protects `main` from half-finished cleanup.
- Easy rollback: remove worktree / abandon branch without dirtying the primary tree.
- Repo convention: `.worktrees/` is gitignored; historical TUI plan used the same layout.

### Before any implementation worktree

1. Primary tree on `main` (or integration branch) must be **clean**:

   ```powershell
   cd D:\Study\project\agent\rove
   git status --short
   git branch --show-current
   ```

2. Decision + plan docs must already be **committed** (this baseline). Creating a
   worktree from a dirty tree leaves uncommitted docs only in one place and
   breaks the “shared baseline” story.

3. Then create the wave worktree **inside the repo**:

   ```powershell
   git worktree add .worktrees/cleanup-w1 -b cleanup/w1 main
   git worktree list
   ```

   Work only under:

   `D:\Study\project\agent\rove\.worktrees\cleanup-w1`

4. Do **not** create `D:\Study\project\agent\rove-cleanup-*` siblings for this series
   unless an explicit exception is recorded.

### Per-wave branches (suggested)

| Wave | Directory | Branch |
|---|---|---|
| W1 | `.worktrees/cleanup-w1` | `cleanup/w1` |
| W2a | `.worktrees/cleanup-w2a` | `cleanup/w2a` (from post-W1 `main`) |
| W2b | `.worktrees/cleanup-w2b` | `cleanup/w2b` |
| W3 | `.worktrees/cleanup-w3` | `cleanup/w3` |

### After merge

```powershell
git checkout main
git pull
git worktree remove .worktrees/cleanup-w1
git branch -d cleanup/w1
```

### Cargo

Do not share `CARGO_TARGET_DIR` across worktrees. Run focused tests in the wave
worktree; full suite before PR from that worktree.

## W3 — First-class `search_code` (document now, implement later)

### Intent

V1 retrieval stays **tools + memory**, not vector RAG.  
Coding UX should not rely on the model inventing `rg` via `run_shell` forever.

### Spec sketch (to refine at implementation)

- Name: **`search_code`** (or `grep` if we rename later — default **`search_code`**).
- Constraints: workspace-bounded paths, timeout, max matches / max bytes, no shell metacharacter footguns.
- Division of labor: structured search → `search_code`; arbitrary commands → `run_shell`.
- **Not** embedding index; **not** LanceDB.

### Work items (when started)

- [x] Tool schema + implementation + safety tests.
- [x] Register in default `tool_registry`.
- [x] Docs: runtime subsystems + tool list.
- [x] Optional: teach prompts/system text to prefer `search_code` for repo search.

### W3 acceptance

- [x] Model can search repo without shell one-liners for common cases.
- [x] Still no built-in vector DB.
