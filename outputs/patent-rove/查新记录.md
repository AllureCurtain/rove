## 2. 国知局命中条目与摘要理解

### 2.1 智能体安全隐患检测

- 文献：CN122087822A，智能体安全隐患检测方法、装置、设备、介质及产品
- 来源 URL：http://epub.cnipa.gov.cn/patent/CN122087822A
- 摘要理解：该方案面向智能体运行时安全，先检测输入文本的意图、困惑度和回译相似度，再基于 MCP 工具元数据分类得到目标工具列表，生成全局工具依赖图，并用图神经网络构建安全检测图以验证依赖图可执行性。重点是对输入、MCP 工具和推理链路做安全隐患检测。
- 局限性：其核心是运行时安全检测和工具依赖图校验，并未公开本地优先状态层、文件工件加 SQLite 可修复索引、提示检查点恢复、提交前模型路由以及 API replay 的组合闭环。

### 2.2 智慧园区多轮问答工具编排

- 文献：CN121765056A，一种基于大语言模型的智慧园区多轮智能问答系统
- 来源 URL：http://epub.cnipa.gov.cn/patent/CN121765056A
- 摘要理解：该系统包含会话状态管理、权限投影、园区数据接入、证据构建、工具编排、大语言模型生成和可信度校验等模块。其工具编排服务于园区问答中的证据生成和业务数据查询。
- 局限性：该方案面向特定园区问答场景，强调权限过滤、证据包和可信度校验；未公开面向通用智能体 runtime 的工具 schema 安全标注、批次并发判定、审批边界和模型调用顺序回写。

### 2.3 LLM 中枢式多智能体工具编排

- 文献：CN121704387A，LLM中枢式多智能体工具编排与虚实闭环进化调度系统
- 来源 URL：http://epub.cnipa.gov.cn/patent/CN121704387A
- 摘要理解：该系统以 LLM 为调度中枢，采集物理环境多模态数据，结合知识图谱和历史任务案例生成约束决策方案，并驱动执行端完成多机协同焊接等虚实闭环调度。
- 局限性：该方案重点是感知、决策、执行、进化的行业调度闭环，未强调本地文件工件、SQLite 索引修复、提示检查点恢复、工具安全审批或提交前模型 fallback 规则。

### 2.4 对话任务中断恢复

- 文献：CN121979478A，对话任务管理方法、系统、车辆、存储介质及程序产品
- 来源 URL：http://epub.cnipa.gov.cn/patent/CN121979478A
- 摘要理解：该方案在车辆语音交互中使用任务栈管理多对话任务，第二任务插入时中断第一任务并保存任务信息，第二任务完成或用户发出恢复指令时弹出任务栈并恢复第一任务。
- 局限性：其恢复对象是车辆多对话任务栈，未涉及模型上下文 token 预算、压缩检查点、工具结果历史、文件加索引的可修复状态层和 API 事件 replay。

### 2.5 多模型路由

- 文献：CN122021864A，一种面向语言模型推理的多模型路由方法、装置和系统
- 来源 URL：http://epub.cnipa.gov.cn/patent/CN122021864A
- 摘要理解：该方案接收用户请求并分类，根据分类概率和置信度阈值选择候选模型；对于学科答题或代码生成模型，还根据语义向量和难度估计器判断是否开启深度思考，从而以较低开销调用合适模型。
- 局限性：其重点是依据任务类型和难度选择开销率低的模型；本案重点是智能体副作用安全，在用户可见文本或工具使用提交之前允许 retry/fallback，提交之后不再切换，并结合健康熔断和事件状态持久化。

### 2.6 大语言模型动态分级提示压缩

- 文献：CN120633874A，一种大语言模型动态分级提示压缩方法、系统、装置和存储介质

- 局限性：其重点是提示内容压缩算法；本案不主张新的压缩模型训练算法，而是把摘要、保留尾部、计划、记忆指针、事件序号和压缩状态组织为可恢复的智能体运行检查点。

- 局限性：其状态修复面向分布式张量更新和冲突消解；本案状态修复是从智能体运行文件工件重建 SQLite 查询索引，并与任务恢复、事件 replay、报告和 pending 状态管理结合。

## 3. 公开框架与工程文档对比

### 3.1 LangGraph checkpointing / persistence

公开资料显示，LangGraph 支持持久化和 checkpoint，用于保存图执行状态、支持恢复、回放和长时运行流程。

局限性：其优势在于图状态和节点执行的持久化，本案区别在于面向本地优先通用 Agent runtime 的组合结构：可读文件工件为事实资产、SQLite 为可修复索引、提示检查点与记忆指针结合、工具安全批处理、提交前模型路由以及本地 API SSE replay。

### 3.2 AutoGen AgentChat state 与工具

公开资料显示，AutoGen AgentChat 提供多智能体会话、工具调用、团队状态保存/加载等能力。

局限性：其重点是多智能体协作抽象和组件状态序列化。本案不是多智能体角色协作方案，而是围绕单个运行时内核的本地状态、恢复、工具安全、模型路由和工作区隔离。

### 3.3 OpenAI Agents SDK tracing / tools

公开资料显示，OpenAI Agents SDK 支持 Agent、工具、handoff、tracing 等构件，用于构建和观测 agent 工作流。

局限性：其更侧重 SDK 级 agent 编排和 tracing。本案重点是运行时本地状态闭环，尤其是文件工件和 SQLite 索引协同修复、提示检查点恢复、提交前 fallback 以及工作区级工具边界。

### 3.4 Google Agent Development Kit sessions / state / artifacts

公开资料显示，Google ADK 提供 sessions、state 和 artifacts 等概念，用于保存 agent 交互和工件。

局限性：其提供通用 agent 应用开发框架概念。本案的区别是把可读工件、SQLite replay、上下文检查点、模型路由提交边界和工具批次安全策略收敛到一个本地优先运行时方法中。

## 4. 检索总结

检索结果表明，现有公开技术已经分别涉及：

- 智能体安全检测和 MCP 工具依赖图校验；
- 场景化问答中的工具编排；
- 多对话任务中断恢复；
- 多模型路由和提示压缩；
- 通用状态修复和 agent 框架持久化。

但尚未见到与本案完全相同的组合方案：以本地优先工作区为边界，通过文件工件与 SQLite 索引协同保存智能体任务状态；以提示检查点和分层记忆实现长任务恢复；以工具安全标注和审批策略决定批次并发/串行；以“提交前可 fallback、提交后不切换”的模型路由保护副作用；并支持 API 重启后的历史 job 查询和 SSE replay。

## 5. 本案与现有技术的本质区别

本案的本质区别不在于单个“提示压缩”“模型选择”或“工具调用”算法，而在于将这些能力组织为一个本地优先、可修复、可恢复、可观测的智能体运行时闭环。该闭环以运行时副作用边界为中心：状态写入可重建，提示上下文可恢复，工具执行可审批且结果顺序确定，模型切换只发生在未提交副作用之前，工作区隔离约束文件、shell 和记忆路径。
